# keepio v0.3 문서 재검토 (기획 / 디자인 / 프론트 / 백엔드 / QA)

> 검토 대상 문서는 `docs/spec/`(01~05)와 `docs/prompts/`(06~07)에 있다. 이 문서는 검토 기록이며, 이후 결정은 `docs/decisions/`의 ADR을 따른다.

## 총평
기존 01~07 문서는 **방향과 MVP 범위 정의에는 타당**하지만, 그대로 구현 명세로 사용하기에는 계약·상태·운영 기준이 부족하다. 아래는 문서 내용을 읽고 발견한 개선사항이며 실제 코드 검증 결과는 아니다.

| 시각 | 타당한 부분 | 보완이 필요한 부분 | 우선순위 |
|---|---|---|---|
| 기획 | 저장→분류→버킷→발행 흐름, MVP 제외 범위 | '미분류' 기준(카테고리 0개인지 AI 미처리인지), 자동 적용 승인, 복구 기간, 재저장 처리, 링크 접근 불가 상태 | P0 |
| 디자인 | 핵심 화면과 템플릿 2종 | API 기반 화면 상태, 디자인 토큰 소스, 컴포넌트 라이브러리 정책, 모바일 공유 실패/오프라인, 편집/발행 충돌 | P0 |
| 프론트 | Next.js/Expo 하이브리드, UI 범위 | 데이터 소유권, 서버/클라이언트 계산 경계, API 호출·캐시 무효화, 인증 브리지, 접근성/반응형, 상태 분리 | P0 |
| 백엔드 | NestJS modular monolith, PostgreSQL, Outbox, 버전 관리 | 인증 제공자 최종 결정, URL 정규화 버전/충돌, Outbox 발행 중복, 소유권 DB 보강, 공개 DTO, quota 원자성 | P0 |
| QA/운영 | 주요 테스트 시나리오 있음 | 테스트 데이터/환경, 자동화 게이트, 실패 증거, 성능·비용 계측, 회귀 매트릭스, 배포·롤백 | P0 |

## 기존 문서 간 확인된 미결정/불일치
1. `04-DATABASE-API.md`는 삭제된 URL 재저장을 '복구 또는 신규'로 미정 처리: PRD의 동일 URL 재사용과 결합하여 **삭제 상태에서 재공유할 때의 UX/API** 확정 필요.
2. AI 카테고리 자동 생성/자동 적용 기준은 제안 수준: 사용자 승인, 동의어 정책, confidence 검증 기준을 분리해야 함.
3. `03-BACKEND-ARCHITECTURE.md`는 JWT 직접 관리 권장이나 인증 서비스 선택과 WebView 토큰 전달은 미검증: Phase 0 PoC 전 확정 금지.
4. `04-DATABASE-API.md`의 부분 UNIQUE 인덱스는 Prisma schema만으로 표현되지 않을 수 있음: SQL migration과 drift 확인 필요.
5. 발행물 '원본 삭제 후 유지'는 정책으로 타당하지만 이미지의 외부 참조가 사라질 수 있음: 자산 보관/삭제·저작권 정책 필요.
6. 공개 URL의 slug 추측 가능성과 검색 색인, 발행 취소 시 CDN 캐시 무효화 규칙 필요.
7. '100개 동시 요청'은 목표 테스트이지 성능 결과가 아님. 실제 측정값으로만 포트폴리오에 기재.
8. API 예시는 확정 계약이 아님. DTO, 오류 코드, 페이징, 필터, 일괄 처리의 부분 실패, idempotency key를 정의해야 함.

## 우선 실행 결정
1. 제품 상태표(북마크 저장/AI 분류/삭제, 발행 draft/published/unpublished)와 권한 매트릭스 작성.
2. API OpenAPI 스키마를 작성하고 타입을 생성/검증. 화면은 실제 응답 모델 기준 설계.
3. 디자인 라이브러리 1개 선정 + 토큰 파일/변형 정책 고정.
4. 테스트 기준과 CI를 코드 구현보다 먼저 마련; 주요 기능의 회귀 테스트를 지속 누적.
5. 공유 수신·인증 브리지·공개 렌더링을 기술 스파이크로 먼저 검증.

## 포트폴리오 원칙
문제→선택지→트레이드오프→구현→실측 검증→남은 한계. '운영 경험'은 실제 운영한 경우에만 주장하고, 미구현 기능은 로드맵으로 명시.
