# ADR-012: 리디렉션 흐름의 실패 문구는 웹 고정 문구 (ADR-009 예외)

- Status: accepted (2026-11-10)
- Context / problem:
  - ADR-009는 오류 문구를 서버 `message`로만 보여 주고, 서버 응답이 없을 때만 `shared`의 고정 문구를 쓰게 한다.
  - 소셜 로그인(FEAT-004)의 start·callback은 브라우저 페이지 이동(302)이다. 실패해도 API가 JSON `{ code, message }`를 웹 화면에 줄 수 없고, 웹은 이동한 주소만 받는다.
  - 주소에 문구를 실으면 누구나 임의 문구를 넣은 링크로 우리 화면에 거짓 안내를 띄울 수 있다(피싱).
- Options:
  - (a) 주소에 `message`를 실어 그대로 표시: 위 피싱 위험.
  - (b) 주소에는 `code`만, 웹이 code → 문구 조회 API를 한 번 더 호출: 규칙은 지키지만 API·호출이 늘고, 실패 이유를 사용자에게 구분해 보여 줄 필요가 없다.
  - (c) 리디렉션 흐름 실패는 `shared`의 고정 문구 1개로 안내(서버 무응답 문구와 같은 취급).
- Decision: (c) (사용자 결정, 2026-11-10).
  - 리디렉션으로 끝나는 흐름의 실패는 주소에 고정 값(`?oauth=failed`)만 싣고, 웹은 `shared`의 고정 문구 하나를 보여 준다. 문구 내용은 주소에서 받지 않는다.
  - 실패 이유(state 불일치·토큰 검증 실패·제공자 오류 등)는 서버 로그에만 남긴다.
  - JSON으로 응답하는 API는 계속 ADR-009를 따른다.
- Consequences / side effects:
  - 웹 `shared`에 고정 문구가 하나 늘어난다. 같은 성격의 흐름(Apple 등)도 같은 문구·같은 주소 값을 쓴다.
  - 사용자는 실패 이유를 구분해 볼 수 없다(재시도 안내만).
- Verification: FEAT-004 AC-03·AC-13 테스트.
- Rollback / migration: revert. 데이터 영향 없음.
