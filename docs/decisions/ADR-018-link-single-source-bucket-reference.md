# ADR-018: 링크는 원본 하나, 버킷은 참조, 공유 페이지는 원본을 따라간다

- Status: accepted (2026-11-21)
- Context / problem:
  - 버킷 상세(BKT-02) 시안을 내 링크(LINK-01) 구조에 맞추면서, 버킷 안에서 링크를 수정하면 내 링크·다른 버킷에도 반영할지 정해야 했다.
  - 버킷 모델은 아직 없다(`prisma/schema.prisma`에 Bucket 없음). 데이터가 쌓이기 전에 정해야 되돌리기 쉽다.
- Options:
  - (a) 원본 하나 + 버킷은 링크를 가리키기만 함(버킷–링크 연결 테이블). 어디서 고쳐도 모든 곳에 반영.
  - (b) 버킷에 넣을 때 복사본 생성. 버킷마다 제목·태그를 따로 가질 수 있지만, 같은 링크의 요약·제목이 여러 벌이 되어 AI 요약·MCP가 어느 것을 볼지 모호해진다.
- Decision: (a) (사용자 결정, 2026-11-21).
  1. **원본 하나:** 링크(Bookmark)는 하나만 있다. 버킷은 연결 행으로 링크를 가리킨다. 내 링크·버킷 어디서 수정해도 같은 원본이 바뀐다.
  2. **버킷별 값은 연결 행에:** 버킷 안 순서("직접 순서")와 나중에 생길 버킷별 메모는 연결 행에 둔다.
  3. **삭제와 빼기:** 링크 삭제는 내 링크에서만. 버킷에서는 "버킷에서 빼기"(연결 행만 삭제).
  4. **버킷에 넣기:** 버킷 화면에는 새 주소 저장이 없다. 새 링크는 내 링크에서 저장하고, 버킷의 "+ 링크 추가"는 이미 저장한 링크에서 골라 넣는다. 내 링크 선택 막대의 "버킷에 추가"도 같은 동작.
  5. **공유 페이지(발행)는 라이브:** 원본을 고치면 공개 페이지에도 바로 반영된다. 이미지 공개 여부는 발행 쪽 설정으로 따로 관리한다(ADR-014 4번 유지).
  6. **안내:** 버킷에서 링크를 수정할 때 폼에 "내 링크와 다른 버킷, 공유 페이지에도 함께 바뀌어요"를 보여 준다.
- Consequences / side effects:
  - DB: 버킷 기능에서 `Bucket`과 연결 테이블(bucket_id, bookmark_id, position, 생성 시각; (bucket_id, bookmark_id) 유일)을 만든다. 마이그레이션은 버킷 Feature 문서에서 정한다.
  - 링크를 휴지통으로 보내면 버킷·공유 페이지에서도 보이지 않아야 한다(연결 행 처리 방식은 버킷 Feature에서 정함).
  - 발행이 라이브이므로, 공개된 페이지의 내용이 원본 수정으로 바뀐다. 발행 시점 고정(스냅샷) 옵션은 D-18로 출시 후 검토.
  - 시안: 디자인 캔버스 "LINK-01 홈 와이어프레임"의 BKT-02 보드.
- Verification: 버킷 Feature 테스트에 "버킷에서 제목 수정 → 내 링크·다른 버킷·공유 페이지에 같은 제목", "버킷에서 빼기 → 내 링크에는 남음"을 넣는다.
- Rollback / migration: 문서 결정이므로 revert. 연결 테이블로 데이터가 쌓인 뒤 복사본 구조로 바꾸려면 데이터 이전이 필요하다.
