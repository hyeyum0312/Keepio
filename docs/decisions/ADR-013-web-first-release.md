# ADR-013: 2026 MVP는 웹 먼저 출시하고 모바일 앱은 2차로

- Status: accepted (2026-11-13)
- Context / problem:
  - 목표는 2026-12-31까지 MVP 출시다. 결정 시점(2026-11-13) 기준 남은 기간은 약 7주다.
  - 완료: FEAT-001(링크 저장)·FEAT-002(목록·삭제·복구)·FEAT-003·004·006(인증과 웹 로그인). 남은 범위: 모바일 앱과 공유 수신(Phase 0), AI 분류(Phase 2), 버킷·발행(Phase 3), 출시 준비(Phase 4).
  - 모바일 앱은 Expo 셸, iOS·Android 공유 확장, WebView 인증 브리지, 앱 토큰 저장소(D-04 남은 부분), Apple 로그인(iOS 출시 시 필수), 스토어 심사가 함께 필요해 7주 안에 웹 범위와 같이 끝내기 어렵다.
- Options:
  - (a) 웹과 앱 동시 출시: 원래 PRD의 핵심인 "외부 앱 공유로 저장"을 첫 출시부터 제공한다. 연내 완료가 어렵고 품질·검증을 줄여야 한다.
  - (b) 앱 먼저 출시: 공유 경험이 핵심이지만 발행·공개 페이지는 결국 웹이 필요하고, 스토어 심사 일정이 통제 밖이다.
  - (c) 웹 먼저 출시, 앱은 2차: 저장 → AI 분류 → 버킷 → 발행의 핵심 흐름을 연내에 웹에서 완주한다. 첫 저장 경험(외부 앱 공유)은 2차까지 약하다.
- Decision: (c) (사용자 결정, 2026-11-13).
  - 1차(웹 MVP, 2026-12-31): 웹 링크 입력 저장, AI 카테고리·태그 추천과 일괄 적용, 버킷 CRUD·순서 변경, 기본형 템플릿 1개로 발행(블록은 제목·소개·링크 카드), 공개 URL·발행 취소, 배포·모니터링·약관·개인정보처리방침.
  - 2차(2027년 1~2월 목표): Expo 앱과 iOS·Android 공유 확장, Android PWA 공유 대상, Apple 로그인, 매거진형 템플릿, 이미지 업로드와 자유 블록 편집.
  - 로그인 수단(ADR-011)은 바꾸지 않는다: 소셜(Google·Kakao) + 이메일/비밀번호. 수집 항목은 이메일과 비밀번호 해시만이다.
- Consequences / side effects:
  - 1차 사용자는 외부 앱에서 공유로 저장할 수 없고 웹에서 URL을 붙여 넣어야 한다. 베타 피드백에서 이 마찰을 확인한다.
  - 배포 호스팅(D-12)을 12월 초에 결정해야 마지막 주에 배포가 몰리지 않는다.
  - Kakao 실연동(키 발급·`email_verified` 확인)은 1차 출시 전에 끝내야 한다.
  - 발행 블록을 제목·소개·링크 카드로 한정하므로 이미지 블록 데이터 모델은 2차에서 추가한다. 1차 스냅샷 구조는 블록 종류 확장이 가능하게 설계한다.
- Verification: 1차 완료 조건 — 웹에서 링크 저장 → AI 분류 → 버킷 → 발행 → 공개 URL 열람까지 완주(spec 05).
- Rollback / migration: 문서 결정이므로 revert. 2차 항목을 1차로 당기면 spec 01·05를 함께 고친다.
