# ADR-019: 기본 앱(북마크)과 실험실(작은 앱 모음)을 나눈다

- Status: proposed
- Context / problem: 일정 트래커(FEAT-012)·방문 일지(FEAT-013)처럼 사용자가 실제로 쓰고 싶은 기능이 생겼지만, 제품 방향(ADR-014, 레퍼런스 라이브러리 3단계 기준)과 성격이 다르다. 기본 앱에 섞으면 방향이 흐려지고, 버리면 쓸 사람(본인)이 원하는 기능을 못 만든다.
- Options:
  - (a) 기본 앱 메뉴에 그대로 추가: 쉽지만 제품 방향·MCP·발행 범위가 섞인다.
  - (b) 별도 앱으로 분리: 깔끔하지만 계정·링크 저장을 다시 만들어야 한다.
  - (c) **기본 앱 + 실험실**: 같은 계정·링크를 쓰되, 실험실 그룹에 작은 앱으로 붙인다.
- Decision: (c). 2026-11-24 사용자 결정.
  1. 기본 앱 = 북마크(홈·내 링크·버킷·발행). 제품 방향 3단계 기준은 기본 앱에만 적용.
  2. 실험실(LAB) = 사이드바 "실험실" 그룹의 작은 앱(일정 트래커, 방문 일지 …). [실험실 둘러보기]에서 켜고 끈다. 켠 것만 사이드바에 보인다.
  3. 공통 재료만 공유: 계정, 링크(내 링크, ADR-018), 카테고리는 앱별, 이미지 업로드 파이프라인. **테이블은 앱별로 분리**해 한 앱을 지워도 다른 곳에 영향이 없게 한다.
  4. 실험실 데이터는 **MCP·발행(공유 페이지)에 포함하지 않는다**.
  5. 실험실은 **웹 전용**. 모바일 앱은 북마크만 제공한다.
  6. 실험실 앱은 작게: 화면 1~2개, 핵심 기능 3~4개. 커지면 정식 기능으로 올리거나 별도 앱으로 뗀다.
- Consequences / side effects: 사이드바가 기본/실험실 두 그룹이 된다(시안 공통 사이드바). 실험실 기능은 제품 방향 문서의 "보류(3단계 밖)" 기준에 걸리지 않는다. 사용자 설정에 실험실 켜기 상태 저장이 필요하다.
- Verification: 실험실 앱을 끄면 사이드바·라우트에서 사라지고 기본 앱 기능(MCP 포함)에 영향이 없는지 E2E.
- Rollback / migration: 실험실 앱 단위로 라우트·테이블 제거. 기본 앱 테이블은 건드리지 않는다.
