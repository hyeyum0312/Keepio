# ADR-014: 제품 방향을 "AI가 꺼내 쓸 수 있는 레퍼런스 라이브러리"로 잡고, 항목·버킷·MCP 구조를 정한다

- Status: accepted (2026-11-15)
- Context / problem:
  - 단순 북마크는 AI 도구가 발달하면서 차별점이 약하다. 실제 사용 패턴은 인스타·유튜브에서 본 모션·AI 영상·마케팅 화면·기획 레퍼런스를 캡처해 카톡으로 보내거나, 메모장에 이름만 옮겨 적은 뒤 피그마·노션·문서로 다시 옮기는 식이다.
  - 첫 사용자는 본인이고, 이후 이직한 회사의 동료(PM/PO, 기획, 디자인)가 함께 쓰는 팀 레퍼런스 라이브러리로 확장할 계획이다.
  - ADR-013은 이미지 업로드를 2차로 두었지만, 레퍼런스 용도에서는 캡처 이미지가 핵심 재료다.
- Options:
  - (a) 단순 북마크 유지: 구현은 가장 작지만 차별점이 없다.
  - (b) 레퍼런스 라이브러리 + MCP: 저장한 버킷을 AI(Claude 등)가 읽어 실제 작업(기획서 초안, 모션 패턴 정리)에 쓰게 한다. 이미지·요약·MCP가 추가로 필요하다.
  - (c) 노션·피그마 직접 연동: 연동 대상마다 구현이 필요하다. MCP를 열면 AI 쪽에서 각 서비스의 MCP로 옮기므로 불필요하다.
- Decision: (b) (사용자 결정, 2026-11-15).
  - **방향:** "AI가 꺼내 쓸 수 있는 내 레퍼런스 라이브러리". 새 기능은 모으기(마찰 없는 저장)·정리(AI 분류·요약)·꺼내 쓰기(MCP, 발행) 중 하나를 강화할 때만 추가하고, 아니면 OPEN-QUESTIONS로 보낸다.
  - **타깃:** 시각 레퍼런스를 많이 모으고 AI로 작업하는 사람(모션, AI 영상, 마케팅 화면, PM/PO 기획).
  1. **항목 구조:** 한 항목 = 링크 0~1개 + 이미지 0~N장 + 메모. 링크·이미지 중 최소 하나 필수. 이미지는 링크의 부연설명이며 수동 업로드. 버킷에는 이미지·영상 링크·페이지 링크가 종류 구분 없이 들어간다. 링크 종류(영상/페이지)는 저장 시 자동 감지하고 표시(썸네일·플레이어)에만 쓴다.
  2. **AI 분류:** 링크가 있으면 링크 내용으로 분류(이미지는 사용 안 함). 이미지만 있는 항목만 저가 비전 모델로 분류하고, 첫 장 썸네일 1장만 보낸다.
  3. **MCP:** 1차(웹 MVP)에 포함. 개인 API 토큰 인증, 읽기 전용, 대상은 버킷으로 한정. 버킷별 "AI 연결 허용" 설정, 기본값 꺼짐. OAuth는 다른 사용자에게 열 때 추가한다.
  4. **발행 시 이미지:** 기본 비공개. 사용자가 이미지별로 공개를 켠다.
  5. **소유 구조:** 버킷은 사용자가 아니라 워크스페이스가 소유한다. 가입 시 개인 워크스페이스 1개를 자동 생성한다. 팀 초대·권한·결제는 나중.
  6. **AI 요약:** 저장 시 요약 필드를 만든다. 재료는 링크 메타데이터 + 첨부 이미지 + 메모. MCP는 이 요약을 그대로 전달한다(MCP가 원본을 직접 보지 않음).
  7. **유튜브:** 자막 기반 요약. 1차 또는 바로 다음 순위.
  8. **인스타그램:** 영상 내용 분석은 하지 않는다(서버 다운로드는 약관 위반). 공개 메타데이터(캡션·썸네일)에 사용자 캡처·메모를 더해 요약한다. Meta oEmbed는 2025-11-03부터 thumbnail_url·author_name 등을 반환하지 않으므로 메타데이터 취득은 불안정할 수 있다.
  - **업로드 기본값(되돌리기 쉬움):** 항목당 이미지 최대 10장, 장당 10MB, JPG·PNG·WEBP·GIF. 원본은 비공개 저장소, 썸네일 별도 생성.
- Consequences / side effects:
  - ADR-013의 2차 항목이던 "이미지 업로드"를 1차로 당긴다. 1차 범위에 이미지 업로드·AI 요약·MCP(개인용)가 추가되어 일정 부담이 커진다.
  - 비용 영향: 파일 저장소(원본+썸네일), 이미지 전용 항목의 비전 모델 호출, 저장 시 요약 호출이 추가된다.
  - DB 영향: 워크스페이스 테이블과 버킷 소유 관계, 항목-이미지 1:N, 요약 필드, 버킷별 MCP 허용 플래그, 개인 API 토큰 저장(해시)이 필요하다. 마이그레이션 계획은 해당 Feature 문서에서 정한다.
  - spec 01(PRD)·04(DB/API)·05(로드맵)를 이 결정에 맞게 고쳐야 한다(별도 작업).
- Verification: 1차 완료 조건에 "이미지 포함 항목 저장 → 버킷 → MCP로 버킷 조회"를 추가한다(spec 05 갱신 시).
- Rollback / migration: 문서 결정이므로 revert. 워크스페이스 소유 구조는 데이터가 쌓인 뒤 되돌리기 어렵다.
