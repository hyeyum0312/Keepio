# Screens — 화면별 정책 문서

화면 하나에 문서 하나. **지금 기준의 최신 정책**만 적는다. 바뀐 이유는 `docs/HISTORY.md`·ADR에, 변경 단위의 수용 기준·API·테스트는 `docs/features/`에 둔다.

- 화면 ID와 목록: [`docs/spec/06-SCREENS.md`](../spec/06-SCREENS.md)
- 시안(디자인 캔버스): [LINK-01 홈 와이어프레임](https://claude.ai/artifact/TVK97VZWLdiXH6GdM6PiBx). 캔버스 메모는 한 줄 요약과 이 문서 경로만 둔다.
- 이전 화면 기획서(artifact)·`spec/02-DESIGN.md`·와이어플로우와 다르면 **이 폴더가 기준**이다.

## 읽고 쓰는 법

- 화면을 만들거나 고치기 전에 해당 문서를 읽는다. 기획이 정해지면 개발 전에 이 문서부터 고친다.
- 항목마다 상태를 붙인다.
  - `[구현]` 지금 코드가 이렇게 동작한다(기준은 코드와 테스트).
  - `[예정]` 시안·결정은 확정, 코드는 아직. 만들 FEAT를 적는다.
  - `[차이]` 코드와 시안이 다르다. 어느 쪽으로 맞출지 정해지면 `[구현]`·`[예정]`으로 바꾼다.
- 개발이 끝나면 `[예정]` → `[구현]`으로 바꾸고 같은 커밋의 HISTORY에 적는다.
- 서버 기능이 없어 화면에 "준비 중"으로만 있는 것은 `[구현] 준비 중`으로 적는다(누를 수 없음, 화면 읽기에 "(준비 중)").

## 공통 규칙 (모든 앱 화면)

- [구현] 글자: 페이지 제목 18px(`text-lg`), 섹션 제목 16px(`text-base`). 줄·카드 안 글자는 화면 문서마다 적는다. 인증 화면은 별도(`text-title`). `docs/standards/DESIGN.md`
- [구현] 서버 기능이 없는 메뉴·버튼은 모양은 같게, 누를 수 없고 "(준비 중)"으로 읽힌다.
- [구현] 고를 것이 0개면 "모두 선택" 체크박스·"선택" 버튼을 그리지 않는다(비활성 아님).
- [구현] 썸네일이 없거나 못 불러오면 링크 ID로 정한 대체 아트(4장). 버킷 썸네일이 없으면 버킷 ID로 정한 중성 톤 아트(8장).
- [구현] 포커스 링은 잉크색 2px + 2px 간격. 입력창은 테두리 색으로 포커스·오류를 보인다(07-BRAND §6).
- [구현] 동작 줄이기(`prefers-reduced-motion`)면 hover 움직임을 끈다.
