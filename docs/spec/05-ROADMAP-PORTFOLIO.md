## 단계별 개발 계획

### Phase 0 — 기술 검증

- [ ] Next.js + NestJS + PostgreSQL 프로젝트 구성
- 모바일 PoC(공유 수신·WebView 인증)는 Phase 5(2차)로 이동(ADR-013).

### Phase 1 — 북마크 기반

- [ ] 인증/인가, 사용자별 격리
- [ ] URL 저장·정규화·중복 방지
- [ ] Soft Delete·복구 및 메타데이터 수집
- [ ] 기본 목록 UI
- **완료 조건:** 동시 동일 URL 요청에도 활성 북마크 하나

### Phase 2 — AI 분류

- [ ] 다중 카테고리/태그 CRUD
- [ ] 기존 카테고리 우선 AI 추천
- [ ] 미분류/분류 완료/일괄 정리 UI
- [ ] 비동기 작업 및 재시도
- **완료 조건:** AI 장애와 무관하게 링크 저장 성공

### Phase 3 — 버킷 및 발행

- [ ] 버킷 CRUD·순서 변경
- [ ] 기본형 템플릿(매거진형은 Phase 5)
- [ ] 블록 편집(제목·소개·링크 카드)·미리보기·초안
- [ ] 발행 스냅샷·버전·공개 URL
- **완료 조건:** 수정 발행 후 같은 URL에서 새 버전 노출

### Phase 4 — 출시

- [ ] 사용량 제한, 접근 통제, SSRF 검증
- [ ] 주요 API 통합/E2E 테스트
- [ ] 웹 배포, 모니터링, 약관·개인정보처리방침
- **완료 조건:** 웹에서 링크 저장 → AI 분류 → 버킷 → 발행 → 공개 URL 열람까지 완주

### Phase 5 — 모바일 앱 (2차)

- [ ] Expo iOS/Android 공유 수신 PoC
- [ ] WebView 인증·세션·딥링크 검증, 앱 토큰 저장소 확정(D-04)
- [ ] Android PWA 공유 대상, Apple 로그인
- [ ] 매거진형 템플릿, 이미지 업로드, 자유 블록 편집
- [ ] 실기기 테스트 및 스토어 출시
- **완료 조건:** 외부 앱 공유 → AI 분류 → 버킷 → 발행까지 완주

## 핵심 테스트

| 시나리오                 | 기대 결과                    |
| ------------------------ | ---------------------------- |
| 동일 URL 동시 저장 100회 | 활성 북마크 1개, 동일 ID     |
| 링크에 카테고리 3개 연결 | 세 카테고리에서 모두 조회    |
| 링크를 버킷 2개에 추가   | 양쪽에서 조회                |
| 버킷에서 제거            | 원본 북마크 유지             |
| 북마크 삭제/복구         | 관계 일관성 유지             |
| 원본 삭제 후 공개 페이지 | 발행 스냅샷 유지             |
| 발행물 수정·재발행       | 기존 slug 유지, 새 버전 노출 |
| 발행 취소                | 공개 접근 중단               |
| AI API 실패              | 저장 성공, 작업 재시도 가능  |
| 저장 한도 동시 초과 요청 | 한도 초과 차단               |
| 타 사용자 ID로 접근      | 거부                         |

## 포트폴리오 핵심 사례

1. **중복 저장 동시성:** DB 유니크 인덱스와 충돌 처리, 부하 테스트 수치.
2. **N:M 관계와 삭제:** Soft Delete/복구/스냅샷 데이터 무결성.
3. **AI 비동기 신뢰성:** Transactional Outbox, BullMQ, 멱등 Worker, 재시도.
4. **발행물 버전:** 불변 스냅샷과 공개 버전 원자적 전환.
5. **운영/보안:** 사용량 쿼터, 권한 검증, SSRF 대응.
6. **AI 협업 하네스:** 규칙을 린트·훅·verify 게이트로 강제, 사람/AI 역할 분담, AI 실수→게이트 전환 기록([ADR-003](../decisions/ADR-003-ai-harness-enforcement.md), [AI-LOG](../qa/AI-LOG.md)).
