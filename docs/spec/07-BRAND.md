# keepio — 브랜드·디자인 기준 (v0.3 후보)

> 상태: **후보**. 변경: v0.2 주 버튼 잉크색·레드는 `accent`로 분리 / v0.3 사용자 레퍼런스(피클, pickle.com) 원칙 반영 — 친근함, UI 무채색·색은 캐릭터, 알약형 버튼, 큰 제목 자간. 레퍼런스는 원칙만 가져오고 화면·문구·캐릭터는 쓰지 않는다. (모두 2026-11-13) 화면 3개(AUTH-01 로그인, LINK-01 내 링크, BKT-02 버킷 상세)를 이 기준으로 그려 본 뒤 D-09에서 확정한다. 확정 전에는 값을 자유롭게 바꾼다. 코드(`globals.css`)에는 확정 후 반영한다.

모든 시안은 이 문서에서 출발하고, 주요 결정마다 아래 원칙 중 무엇을 따랐는지 밝힌다. 취향을 반영할 때는 화면 하나가 아니라 원인이 되는 원칙·토큰을 고친다.

## 1. 브랜드 성격

| 키워드      | 디자인에서 뜻하는 것                                                 |
| ----------- | -------------------------------------------------------------------- |
| 가볍다      | 넓은 여백, 얇은 테두리, 그림자 대신 배경 차이로 면 구분, 짧은 움직임 |
| 깔끔하다    | 강조색은 화면당 한 곳, 무채색 중심, 정렬선 최소화(왼쪽 정렬 기본)    |
| 살짝 귀엽다 | 둥근 모서리, 캐릭터 심볼, 다정한 말투("~해요")                       |
| 친근하다    | 알약형 버튼, 크게 둥근 카드, 캐릭터가 사용자를 맞이하는 첫 화면      |

제품 원칙(02-DESIGN): 콘텐츠 중심의 미니멀. 사용자가 저장한 링크가 주인공이고 UI는 뒤로 물러난다.

## 2. 디자인 원칙과 근거

1. **주인공 하나**: 한 화면에서 가장 중요한 행동 하나만 주 버튼(`primary`)으로 쓴다. 강조가 둘이면 아무것도 강조되지 않는다(시각적 위계). 그 화면의 주인공이 무엇인지 먼저 정한다(예: 로그인은 소셜 버튼이 주인공이라 이메일 로그인 버튼은 그보다 약해야 한다).
2. **강조 수단은 하나씩**: 크기·굵기·색 중 하나로 위계를 만든다. 셋을 동시에 쓰지 않는다.
3. **60-30-10 색 비율**: 배경·무채색 약 60%, 표면·보조 무채색 약 30%, 강조색 10% 이하.
4. **가까운 것은 묶인다**: 관련 요소 사이 간격 < 그룹 사이 간격(게슈탈트 근접성). 예: 라벨과 입력창 8px, 입력 그룹 사이 16px, 섹션 사이 32px.
5. **같은 역할은 같은 모양**: 같은 동작은 화면이 달라도 같은 컴포넌트·같은 위치(일관성). 새 모양을 만들기 전에 기존 컴포넌트를 찾는다.
6. **접근성이 먼저**: 글자 대비 4.5:1 이상, 입력창 테두리·포커스 같은 UI 요소 3:1 이상(WCAG 2.2 AA), 터치 영역 44px 이상, 색만으로 상태를 전달하지 않는다.
7. **콘텐츠가 주인공**: 장식 요소는 정보를 줄 때만 쓴다. 썸네일·제목이 UI보다 먼저 보이게 한다.
8. **UI는 무채색, 색은 캐릭터가**: 버튼·입력·글자·면은 무채색 단계로만 만든다. 화면의 색은 캐릭터 심볼(브랜드 표현 영역)과 사용자 콘텐츠(썸네일)가 가져온다. 브랜드 레드 `accent`는 포커스·완료 표시처럼 작은 표시에만 쓴다.

- standards에 없던 토큰 2개를 추가 제안한다. `muted-foreground`: 보조 글자가 본문과 같은 색이면 위계가 사라짐. `input`: 장식용 `border`(1.36:1)로는 입력창이 3:1 기준을 못 넘음.
- 주 버튼은 잉크색이다(v0.2). 레드를 주 버튼에 쓰면 소셜 버튼·캐릭터와 경쟁하고 강조색이 10%를 넘었다(원칙 1·3). 레드는 `accent`·`focus-ring`·로고·캐릭터에만 아껴 쓴다.
- `accent`는 배경 대비 4.16:1이라 본문 글자색으로 쓰지 않는다(표시·선·점 같은 UI 요소 3:1 기준만 충족).
- standards에 없던 `accent`를 추가 제안한다: 브랜드 색을 주 버튼과 분리해야 패밀리 서비스에서 대표색만 바꿀 수 있다.
- 기존 `ai` 값 `#7F77DD`는 흰 배경 대비가 낮아 `violet-600`으로 제안한다.
- 소셜 로그인 버튼은 **제공자 가이드가 이 문서보다 우선**한다. 카카오: 배경 `#FEE500`, 심볼 검정, 글자 검정 85%, 반경 12px, 문구 "카카오 로그인"(작게 할 때 축약형 "로그인"), 심볼만 있는 버튼 불가. Google: 표준 컬러 "G"(크기·색 변경 불가), 라이트·다크 테마 색, 문구 "Google 로그인", 다른 소셜 버튼과 같은 크기·무게. 두 버튼은 같은 폭·높이 48px·반경 12px로 맞춘다. 출처: [카카오 로그인 디자인 가이드](https://developers.kakao.com/docs/latest/ko/kakaologin/design-guide), [Sign in with Google Branding Guidelines](https://developers.google.com/identity/branding-guidelines)(2026-11-13 확인).

### 3.3 브랜드 토큰 (3층: 서비스별)

서비스마다 바꾸는 층. 지금은 Keepio 하나뿐이다.

| 토큰                                  | Keepio                |
| ------------------------------------- | --------------------- |
| `brand` (대표색 원재료)               | `red` 계열            |
| `accent`·`focus-ring`이 가리키는 단계 | 위 2층 표             |
| 로고·심볼                             | 레드 심볼 라이트/다크 |

## 4. 라이트·다크 모드

- 1차부터 두 모드를 함께 출시한다. 1차는 시스템 설정(`prefers-color-scheme`)만 따르고, 수동 토글은 2차.
- 다크는 반전이 아니라 역할 토큰마다 다크 값을 둔다. 순수 검정·흰색은 쓰지 않는다.
- 다크에서는 그림자가 보이지 않으므로 면 구분은 `border`·배경 단계로만 한다.
- 로고·심볼은 모드별 에셋으로 교체한다.
- 공개 발행 페이지는 보는 사람의 모드가 아니라 템플릿 모드로 고정한다(기본형은 라이트).
- 검수: 화면마다 라이트·다크 스크린샷 두 장.

## 5. 글자

- 글꼴: 우선 시스템 글꼴 스택(추가 다운로드 없음). 한글 웹폰트(예: Pretendard) 도입은 D-09에서 결정한다(의존성·로딩 비용).
- 크기(px): `12` 보조 · `14` 본문·라벨 · `16` 입력값(iOS 확대 방지)·강조 본문 · `20` 작은 제목 · `24` 화면 제목 · `32` 화면 헤드라인 · `40` 무대형 헤드라인 · `48` 랜딩 헤드라인. 16 위로 약 1.2~1.25배씩 올리고, 헤드라인 단계는 대비를 위해 간격을 넓힌다.
- 자간: 24px 이상 제목은 `-0.02em`, 40px 이상은 `-0.03em`. 큰 글자가 느슨해 보이지 않게 한다. 본문은 기본값.
- 굵기: 400 본문, 600 제목·버튼. 두 단계만 쓴다.
- 줄 높이: 본문 1.5, 제목 1.3.

## 6. 간격·크기·모양

- 간격: 4px 단위 — `4 · 8 · 12 · 16 · 24 · 32 · 48`. 규칙은 원칙 4(근접성).
- 높이: 버튼·입력창 48px(터치 44px 이상, 모바일·PC 공통).
- 반경: `full`(알약형) 우리 버튼(주·보조)·칩 · `12` 입력창·소셜 버튼 · `24` 카드·패널 · `full` 아바타. 같은 줄에 놓이는 요소끼리는 반경을 맞춘다.
- 테두리 두께: 1px. 포커스 링 2px + 2px 간격.
- 그림자: 쓰지 않는 것이 기본. 떠 있는 요소(메뉴·모달)만 한 단계.
- 아이콘: 선 아이콘, 24px 격자, 선 두께 1.5px. 라이브러리는 컴포넌트 라이브러리 선정(standards DESIGN 2번)과 함께 정한다.

## 7. 캐릭터 심볼

- 브랜드 표현 영역(랜딩, 로그인, 빈 상태, 완료 안내)에서만 쓴다. 그 안에서는 패밀리 캐릭터를 여럿 써서 "무대"를 만들 수 있다(v0.3). 작업 화면(목록·편집기) 안에는 넣지 않는다.
- 캐릭터는 장식이므로 `alt=""`, 글자·버튼을 가리지 않는다. 캐릭터 위의 글자는 배경 대비 기준(4.5:1)을 따로 확인한다.
- 눈 굴리는 GIF는 조용한 반복만. `prefers-reduced-motion`이면 정지 SVG.

## 8. 움직임

- 길이 150~250ms, 들어올 때 감속(ease-out). 상태 전달(열림·저장됨)에만 쓰고 장식 애니메이션은 캐릭터 외에는 쓰지 않는다.
- `prefers-reduced-motion`이면 위치 이동 없이 투명도만.

## 9. 말투

- "~해요"체. 짧게, 능동으로. 버튼은 동사로 끝낸다("로그인", "저장하기").
- 오류 문구는 무엇이 잘못됐고 무엇을 하면 되는지 한 문장으로. 사용자 탓을 하지 않는다. 문구 원본은 서버(ADR-009).

## 10. 토큰 운영 원칙

1. **확정은 늦게**: 화면 3개를 그려 본 뒤 D-09에서 확정. 그 전에는 후보.
2. **적게 시작**: 필요한 화면이 생겼을 때만 추가한다. 미리 만들지 않는다.
3. **3층 구조**: 원재료(1층) → 역할(2층) → 브랜드(3층). 화면은 역할 토큰만 쓴다. 브랜드 색을 바꾸면 3층만, 느낌을 바꾸면 2층만 고친다.
4. **표현 영역은 별도 허용**: 랜딩 첫 화면, 로그인 좌측 패널, 발행 템플릿은 그 영역 전용 토큰을 둘 수 있다. 앱 작업 화면은 공용 토큰만.
5. **예외는 토큰으로**: 기준을 벗어나야 하면 값을 직접 쓰지 않고 토큰을 추가하고 이유를 한 줄 남긴다(standards DESIGN 5번 절차).

## 11. 패밀리 서비스

- 방식: 1·2층(원재료·역할·컴포넌트)은 공유, 3층(대표색·로고)만 서비스별.
- 대표색 후보: 기존 로고 컬러 세트 — 레드(Keepio), 옐로, 탠저린, 블루, 퍼플. 같은 심볼에 색만 바꿔 한 가족으로 보이게 한다.
- 서비스별 대표색도 2층 대비 기준(버튼 글자 4.5:1 등)을 통과하는 단계를 고른다.

## 12. 시안 피드백 방식

- 시안에는 주요 결정마다 따른 원칙 번호를 붙인다(예: "로그인 버튼만 강조색 — 원칙 1").
- 사용자 피드백은 레퍼런스와 함께 **좋은 점 · 싫은 점 · 유지할 것**을 한 줄씩.
- 반영은 해당 원칙·토큰을 고치고 이 문서의 버전과 변경 이유를 남긴다.
