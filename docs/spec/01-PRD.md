# keepio — MVP 기획 및 개발 요구사항 (PRD v0.3)

## 제품 목표

외부 앱에서 링크 공유 → 저장 → AI 분류 → 카테고리/태그/버킷으로 소비 → 템플릿으로 편집·발행 → 공개 URL 공유.

## 핵심 도메인

| 개념               | 역할                                                |
| ------------------ | --------------------------------------------------- |
| Bookmark           | 사용자가 저장한 원본 URL과 메타데이터               |
| Category           | 탐색을 위한 다중 분류. 한 링크에 여러 카테고리 허용 |
| Tag                | 장소·속성·맥락 등 세부 키워드                       |
| Bucket             | 목적별 링크 컬렉션. 한 링크가 여러 버킷에 속함      |
| Template           | 발행 페이지의 레이아웃 및 블록 스타일               |
| Publication        | 독립 URL을 갖는 편집·공개 콘텐츠                    |
| PublicationVersion | 특정 시점의 불변 발행 스냅샷                        |

## MVP 범위

- 계정 인증과 사용자 데이터 격리
- iOS/Android 외부 앱의 URL 공유 수신
- URL 정규화, 사용자별 중복 검사, 메타데이터 수집
- AI 카테고리·태그 추천, 기존 카테고리 우선, 수동 수정
- 전체/미분류/분류 완료 목록, 검색·필터·일괄 적용
- 카테고리·태그·버킷 CRUD 및 버킷 내 순서 변경
- 버킷 또는 개별/카테고리별 링크 선택으로 발행물 생성
- 기본형/매거진형 템플릿, 텍스트·이미지·링크 블록 편집
- 초안·미리보기·발행·수정 발행·발행 취소
- 사용량 제한 구조, Soft Delete, 복구, 장애 처리

## AI 분류 정책

1. 기존 카테고리와 별칭을 조회해 재사용 우선.
2. `호텔`/`숙소`는 의미 유사성을 인식하되 사용자가 의도적으로 분리한 경우 강제 병합하지 않음.
3. `호텔 A`/`호텔 B`처럼 개별 대상은 카테고리보다 태그/버킷 후보로 제안.
4. AI는 1~3개 카테고리를 기본 추천하되 DB에서는 복수 연결 허용.
5. 낮은 확신도는 미분류 유지. 신규 카테고리 생성·기존 카테고리 병합은 서버 검증 및 사용자 정책에 따름.
6. AI 결과는 구조화된 JSON으로 받고 ID·소유권·중복을 서버에서 검증.
7. AI 장애가 발생해도 북마크 저장은 성공해야 함.

## 데이터 생명주기

- 동일 계정의 동일 정규화 URL은 기존 북마크 ID 반환. 새 버킷 지정 시 기존 북마크를 연결.
- 링크 삭제는 Soft Delete; 활성 목록에서 숨기고 복구 기간 동안 관계 유지.
- 카테고리 삭제 시 북마크 자체는 보존. 버킷 삭제 시 링크 자체는 보존.
- 발행물은 URL·제목·본문·이미지 참조를 스냅샷으로 저장하여 원본 수정/삭제와 독립.
- 발행물 수정은 새 버전을 생성하고 기존 공개 slug 유지. 초안은 공개 버전에 즉시 반영하지 않음.
- 공개 발행은 비로그인 열람. 비밀 URL을 접근 제어로 간주하지 않으며, 공개 경고와 발행 취소 제공.

## 비기능 요구사항

- DB 제약과 트랜잭션으로 중복·동시성 처리
- 사용자별 권한 검증, 공개/비공개 경계 분리
- 외부 URL 요청 시 SSRF·리다이렉트·내부 IP 차단
- AI 작업 재시도·멱등성·실패 상태 추적
- 플랜별 북마크·발행물·AI 호출·저장량 제한을 설정 기반 관리
- 모바일/데스크톱 반응형, 빈 상태/오류/로딩/성공 상태

## MVP 제외

사용자 제작 템플릿 빌더, 공동 편집, 소셜 피드, 브라우저 확장, 결제, 고급 분석, 완전 네이티브 UI.
