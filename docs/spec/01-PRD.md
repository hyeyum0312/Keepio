# keepio — MVP 기획 및 개발 요구사항 (PRD v0.3)

## 제품 목표

**"AI가 꺼내 쓸 수 있는 내 레퍼런스 라이브러리"** (ADR-014). 링크·캡처 이미지 저장 → AI 분류·요약 → 카테고리/태그/버킷으로 정리 → MCP로 AI 작업에 활용하거나 템플릿으로 편집·발행 → 공개 URL 공유.

타깃: 모션·AI 영상·마케팅 화면·기획(PM/PO)처럼 시각 레퍼런스를 많이 모으고 AI로 작업하는 사람. 첫 사용자는 개인, 이후 팀(회사 동료)으로 확장한다.

## 기능 판단 기준

새 기능은 다음 중 하나를 강하게 만들 때만 추가하고, 아니면 `OPEN-QUESTIONS.md`로 보낸다.

1. 모으기: 링크·캡처를 마찰 없이 저장
2. 정리: AI 분류·요약으로 "이름만 적어둔 메모" 상태를 없앰
3. 꺼내 쓰기: MCP로 AI가 버킷을 참고해 작업, 발행으로 공유

## 핵심 도메인

| 개념               | 역할                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| Workspace          | 버킷의 소유 단위. 지금은 가입 시 개인 1개, 팀은 나중                                               |
| Bookmark           | 레퍼런스 항목. 링크 0~1개 + 이미지 0~N장 + 메모, 둘 중 하나 필수                                   |
| BookmarkImage      | 항목에 붙는 수동 업로드 이미지(링크의 부연설명)                                                    |
| Category           | 탐색용 분류. 한 링크는 0~1개(ADR-015), 없으면 미분류                                               |
| Tag                | 장소·속성·맥락 등 세부 키워드                                                                      |
| Bucket             | 목적별 항목 컬렉션. 이미지·영상 링크·페이지 링크를 종류 구분 없이 담고, 한 항목이 여러 버킷에 속함 |
| API Token          | MCP 연결용 개인 토큰(읽기 전용)                                                                    |
| Template           | 발행 페이지의 레이아웃 및 블록 스타일                                                              |
| Publication        | 독립 URL을 갖는 편집·공개 콘텐츠                                                                   |
| PublicationVersion | 특정 시점의 불변 발행 스냅샷                                                                       |

## MVP 범위

MVP는 2단계로 출시한다(ADR-013). 1차는 웹(2026-12-31), 2차는 모바일 앱(2027년 1~2월 목표). 아래 목록 중 2차 항목은 표시한다.

- 계정 인증과 사용자 데이터 격리
- iOS/Android 외부 앱의 URL 공유 수신 (2차)
- URL 정규화, 사용자별 중복 검사, 메타데이터 수집
- 이미지 수동 업로드(링크와 함께 또는 이미지만), 링크 종류(영상/페이지) 자동 감지(표시용)
- 저장 시 AI 요약(링크 메타데이터 + 첨부 이미지 + 메모)
- AI 카테고리·태그 추천, 기존 카테고리 우선, 수동 수정
- 전체/미분류/분류 완료 목록, 검색·필터·일괄 적용
- 카테고리·태그·버킷 CRUD 및 버킷 내 순서 변경
- MCP(개인 토큰, 읽기 전용): 버킷 목록·검색·항목·요약 조회. 버킷별 "AI 연결 허용"(기본 꺼짐)한 버킷만 대상
- 버킷 또는 개별/카테고리별 링크 선택으로 발행물 생성
- 기본형 템플릿, 제목·소개·링크 카드 블록 편집. 항목 이미지는 발행 시 기본 비공개, 이미지별로 공개를 켠 것만 노출 (매거진형 템플릿, 자유 블록 편집은 2차)
- 유튜브 자막 기반 요약 (1차 여유가 없으면 바로 다음 순위)
- 초안·미리보기·발행·수정 발행·발행 취소
- 사용량 제한 구조, Soft Delete, 복구, 장애 처리

## AI 분류 정책

1. 기존 카테고리와 별칭을 조회해 재사용 우선.
2. `호텔`/`숙소`는 의미 유사성을 인식하되 사용자가 의도적으로 분리한 경우 강제 병합하지 않음.
3. `호텔 A`/`호텔 B`처럼 개별 대상은 카테고리보다 태그/버킷 후보로 제안.
4. AI는 카테고리 1개와 태그 여러 개를 추천한다(ADR-015). 적용은 사용자 승인 후(D-03).
5. 낮은 확신도는 미분류 유지. 신규 카테고리 생성·기존 카테고리 병합은 서버 검증 및 사용자 정책에 따름.
6. AI 결과는 구조화된 JSON으로 받고 ID·소유권·중복을 서버에서 검증.
7. AI 장애가 발생해도 북마크 저장은 성공해야 함.
8. 링크가 있는 항목은 링크 내용으로 분류하고 이미지는 쓰지 않는다. 이미지만 있는 항목만 저가 비전 모델로 분류하며 첫 장 썸네일 1장만 보낸다(ADR-014).
9. 인스타그램은 영상 내용을 분석하지 않는다(서버 다운로드 금지). 공개 메타데이터(캡션·썸네일)와 사용자 캡처·메모로 요약한다. 메타데이터 취득 실패는 저장 실패가 아니다.

## 카테고리·태그·버킷 정책 (ADR-015)

| 구분     | 목적                | 링크당                     | 순서              |
| -------- | ------------------- | -------------------------- | ----------------- |
| 카테고리 | 찾기: 서랍 하나     | 0~1개, 없으면 미분류       | 이름순            |
| 태그     | 좁히기: 키워드      | 0~10개, 입력하면 자동 생성 | 이름순            |
| 버킷     | 발행·AI 참고용 모음 | 여러 버킷에 중복 가능      | 버킷 안 직접 정렬 |

- 저장 시 카테고리 선택은 선택 사항. 이동은 연결만 바꾸고 원본·태그·버킷은 유지한다.
- 태그는 링크에 붙는다. 카테고리 화면은 그 카테고리 링크에 쓰인 태그만 필터로 보여 준다.
- 카테고리 삭제는 영구 삭제(링크는 미분류로), 병합은 옛 이름을 별칭으로 남긴다.
- 이름 1~20자(태그 1~30자), 정규화 후 중복 금지. 상한: 사용자당 카테고리 100·태그 500(임시값, D-07과 함께 조정).
- 상세: `docs/features/category-tag.md`(FEAT-008)

## 데이터 생명주기

- 동일 계정의 동일 정규화 URL은 기존 북마크 ID 반환. 새 버킷 지정 시 기존 북마크를 연결.
- 삭제한 링크를 다시 저장하면 새로 만들지 않고 복구를 안내한다(D-01).
- 링크 삭제는 Soft Delete; 활성 목록에서 숨기고 복구 기간 동안 관계 유지.
- 카테고리 삭제 시 북마크 자체는 보존. 버킷 삭제 시 링크 자체는 보존.
- 발행물은 URL·제목·본문·이미지 참조를 스냅샷으로 저장하여 원본 수정/삭제와 독립.
- 발행물 수정은 새 버전을 생성하고 기존 공개 slug 유지. 초안은 공개 버전에 즉시 반영하지 않음.
- 공개 발행은 비로그인 열람. 비밀 URL을 접근 제어로 간주하지 않으며, 공개 경고와 발행 취소 제공.

## 비기능 요구사항

- DB 제약과 트랜잭션으로 중복·동시성 처리
- 사용자별 권한 검증, 공개/비공개 경계 분리
- 외부 URL 요청 시 SSRF·리다이렉트·내부 IP 차단
- 이미지 업로드: 항목당 최대 10장, 장당 10MB, JPG·PNG·WEBP·GIF(파일 시그니처 검증). 원본은 비공개 저장소, 썸네일 별도
- MCP는 토큰 소유자의 "AI 연결 허용" 버킷만 읽는다. 토큰은 해시로 저장하고 폐기 가능
- AI 작업 재시도·멱등성·실패 상태 추적
- 플랜별 북마크·발행물·AI 호출·저장량 제한을 설정 기반 관리
- 모바일/데스크톱 반응형, 빈 상태/오류/로딩/성공 상태

## MVP 제외

사용자 제작 템플릿 빌더, 공동 편집, 팀 워크스페이스(초대·권한), MCP OAuth·쓰기, 영상 직접 분석, 소셜 피드, 브라우저 확장, 결제, 고급 분석, 완전 네이티브 UI, 버킷 중첩(버킷은 한 단계), 버킷 후보 비교/결정 화면(MVP 이후 재검토).
