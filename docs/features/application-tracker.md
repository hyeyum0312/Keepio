# FEAT-012 — 트래커: 일정·단계·결과를 표와 달력으로

- Status: Draft
- Updated: 2026-11-24
- Related: ADR-014(제품 방향), ADR-019(실험실 구조, 제안), FEAT-001(링크 저장), FEAT-013(방문 일지), D-21(제안, 아래)
- 시안: Keepio 일정 트래커 시안 캔버스(보드 1·3이 1차 기준)

## 1차 범위 (2026-11-24 확정, 이 절이 아래 내용보다 우선)

이 명세는 아이디어를 넓게 모은 초안이다. **1차 구현 범위는 이 절만이다.** 아래 AC 중 여기 없는 것은 보류 또는 삭제.

- 위치: 실험실(ADR-019)의 "일정 트래커". **웹 전용**, 모바일 앱에서는 제공하지 않는다. 구현은 AI 전담.
- 1차에 하는 것
  1. **링크로 일정 등록**(AC-27·28·30 축소판): 지원한 공고 링크를 읽어 단계를 일괄 등록. 가져올 곳은 [내 링크에서 고르기] / [직접 넣기](넣은 링크는 내 링크에도 저장, ADR-018). 단계를 못 찾은 링크도 제목·링크만 등록하고 상태 "날짜 미정" → 사이드 패널 [+ 단계 추가]로 나중에 채운다. AI 추출·이미지·문자·PDF는 1차 제외(규칙 읽기 + 붙여넣기만).
  2. **필터해서 보기**: 달력 / 임박순, 카테고리 칩(AC-18~20), 상태 칩(AC-36). 상태: 결과 입력 필요 · 진행 중 · 관심 공고 · 탈락 · **포기** · 최종 합격·완료 · **날짜 미정**.
  3. **상태 처리**: 합격·불합격(AC-06·07·11). **불합격 또는 [이 지원 포기] 시 이후 단계를 달력에서 지운다**(되돌리기 [결과 취소]/[다시 진행] 시 복구). 탈락=기관 판정, 포기=본인 결정으로 상태를 나눈다.
  4. **대출 계산 외부 링크**: 상단 [대출 계산 ↗] → 토스 DSR 계산기(새 탭, 입력값 전달·저장 없음). 링크 주소는 서버 설정.
  5. **오늘 일정 팝업**(알림 대체): 일정 페이지를 열면 "오늘 일정 N건" 배너 → [오늘 일정만 보기]로 오늘 필터 적용·해제.
- 항목 타입: **청약 / 임장**. 같은 달력에 표시(임장은 흰 바탕 + 카테고리색 테두리). 사이드 패널은 타입별로 다르다 — 청약: 상태·단계·내용·이미지·링크 / 임장: 방문 일시·결과(확정·고민중·탈락)·체크리스트 진행률·메모·매물 링크·부동산. 임장 기록의 상세 관리는 FEAT-013(방문 일지).
- **삭제(하지 않음)**: 이메일 알림(AC-09), 댓글(AC-32), 새 공고 받기·조건 구독·공고 페이지 자동 읽기(AC-35, D-25, D-26).
- **보류**: 공유(AC-24~26, D-24), PDF 읽기(있을 때만, 시안 8), 문자·이미지·AI 추출(AC-29·31, AC-28의 모델 단계), 공고 사이트 바로가기 묶음, 계약 단계 대출 정리(시안 10), 버킷 링크 넣기(AC-33·발행 이후), 청약홈 달력 링크(AC-34), 내 집 마련 도우미(D-27: 가점·정책대출 자가진단은 외부 링크로만).
- 1차 화면: 시안 1(달력 + 사이드 패널: 오늘 팝업, 상태 칩, 포기, 타입별 패널), 시안 3(링크 등록: 내 링크/직접 넣기, 단계 없음 카드).

## 목적 및 비범위

- 사용자 문제: 청약·채용·시험·공모전, 여행·웨딩 준비처럼 "지원 → 발표 → 다음 단계"로 이어지는 일정을 메모나 머릿속으로 관리하다 발표일을 놓치거나 지금 어느 단계인지 헷갈린다.
- 범용 트래커로 만든다. 단계 이름은 사용자가 직접 적는다(서류 발표, 면접, 시험 준비, 취준, 출발일, 잔금 등 무엇이든).
- 새 페이지 하나("일정")로 추가한다. 일정은 **링크 단위**로 연결한다. 버킷에는 여러 성격의 링크가 섞여 있으므로(레퍼런스, 레스토랑 예약, 숙소 등) 버킷 전체가 아니라 날짜가 있는 링크만 달력에 올린다.
- 이번 작업에서 하지 않는 것:
  - 링크 카테고리(FEAT-008)와 일정 카테고리 공유(성격이 달라 분리. 링크 카테고리는 레퍼런스 분류, 일정 카테고리는 생활 영역)
  - 단계별 카테고리(항목 단위만)
  - 앱 푸시(앱 출시 후 같은 알림 이벤트에 채널만 추가)
  - 외부 캘린더 연동(구글 캘린더, ICS 구독)
  - 첨부파일(PDF·HWP) 안의 일정 읽기. 페이지 본문만 읽는다(AC-28)
  - 사이트를 주기적으로 돌며 새 공고 수집
  - 노션 연동. 노션을 계속 쓰는 사람에겐 이 기능이 필요 없고, 목표는 노션 정리를 대신하는 것. 옮겨 오는 길은 붙여넣기(AC-27) 하나로 충분
  - 홈 화면 위젯, 섹션 위치 변경(별도 기능)
  - 팀 공유
  - MCP 제공(일정·일정 묶음은 AI 연결 대상이 아님)

## 검토한 대안

| 선택지                                                                    | 장점                                                                                                             | 단점                                                                                                                 |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| A. 트래커를 별도 항목으로 두고, 링크(Bookmark)는 항목·단계마다 0~1개 연결 | 관련 링크만 골라 달력에 올림. 링크 없는 일정도 가능. 버킷 연결은 링크를 통해 자연히 생김(ADR-018 링크 원본 하나) | 테이블 2개 추가                                                                                                      |
| A'. 트래커를 버킷에 연결                                                  | 프로젝트 단위로 묶기 쉬움                                                                                        | 버킷 안 무관한 링크까지 엮임. 버킷 구현 전엔 못 만듦 → 채택 안 함. 대신 버킷의 공유 링크를 일정 링크로 넣는다(AC-33) |
| B. Bookmark에 날짜·상태 필드 추가                                         | 테이블 추가 없음                                                                                                 | 모든 링크에 쓰지 않는 필드가 붙음. 단계가 여러 개라 결국 하위 테이블 필요                                            |
| C. 외부 캘린더(ICS)로 내보내기만                                          | 구현 작음                                                                                                        | 단계·결과 관리가 안 됨. 요구의 핵심이 빠짐                                                                           |

- 추천 및 근거: A. 단계가 여러 개이고 결과가 단계마다 붙으므로 별도 구조가 맞다. 연결은 링크 단위로 해서 관련 링크만 일정이 된다. 버킷 화면은 "버킷 안 링크 중 일정이 있는 것"을 계산해서 보여 주면 되므로 버킷에 별도 연결이 필요 없다.
- 관련 ADR: 제품 방향(ADR-014)에 "링크에 일정을 붙인다"를 추가할지 D-21로 결정한다.

## 개념

- **트래커 항목(Tracker)**: 이름(필수), 메모(선택), 대표 링크(선택, 예: 청약 공고), 결과 방식, 마감 상태.
- **결과 방식**(항목 만들 때 고름, 나중에 못 바꿈):
  - 합격·불합격: 지원·시험용. 단계마다 [합격] [불합격].
  - 완료만: 여행·웨딩·납부 같은 일정용. 단계마다 [완료]만 있고 탈락이 없다. 단계는 미리 여러 개 넣을 수 있다(AC-08 예외).
- **단계(Stage)**: 항목 안에 순서대로 쌓인다. `이름`, `날짜`(필수), `시간`(선택), `링크`(선택, 예: 레스토랑 예약 링크), `결과`.
- 예: 항목 "도쿄 여행"(완료만) → 단계 "출발"(항공권 링크), "스시 예약"(예약 링크), "귀국".
- **항목 상태(서버가 계산)**:
  - 진행 중: 마지막 단계가 대기, 또는 합격 후 다음 단계를 아직 안 정함
  - 탈락(합격·불합격 방식): 어느 단계든 불합격 처리됨
  - 최종 합격(합격·불합격 방식): 사용자가 "최종 합격으로 마치기"를 누름
  - 완료(완료만 방식): 모든 단계가 완료됨

## 사용자 흐름 및 수용 기준

- [ ] AC-01 항목 만들기: 이름, 결과 방식, 첫 단계(이름·날짜)를 넣어 저장한다. 링크는 선택이며 내 링크에서 고른다(새 주소 저장은 내 링크에서, ADR-018 4번과 같은 원칙).
- [ ] AC-16 링크에서 바로 추가: 링크의 ⋯ 메뉴 [일정에 추가] → 기존 항목에 단계로 넣거나 새 항목을 만든다. 그 링크가 단계에 미리 연결된다.
- [ ] AC-02 전환: 왼쪽 영역에서 [달력] / [임박순]을 눌러 전환한다. 마지막 선택을 기억한다(브라우저 저장, 실패해도 기본값 달력).
- [ ] AC-03 임박순: 다가오는 단계를 날짜가 가까운 순으로 한 줄씩. 줄마다 카테고리 색 표시, 항목 이름, 단계 이름, 날짜, D-day(오늘은 "D-Day", 3일 이내는 강조). 지난 대기 단계("결과를 입력해 주세요")는 맨 위, 마감된 항목은 숨기고 [끝난 지원 보기]로 펼친다.
- [ ] AC-04 달력: 월 단위로 한눈에 본다. 날짜 칸에 그날 단계를 카테고리 색 막대(항목 이름 + 단계 이름)로 보여 주고, 칸 높이를 넘으면 "+N"으로 접는다. [오늘] 버튼과 월 이동.
- [ ] AC-18 카테고리: 사용자가 일정 카테고리를 만들고(이름 + 색) 항목마다 0~1개 지정한다. 예: 청약(주황), 채용(파랑), 여행(초록), 웨딩(분홍). 지정 안 한 항목은 회색 "기타".
- [ ] AC-19 색 직접 설정: 카테고리마다 색을 고른다. 팔레트 12색에서 고른다(라이트·다크 모드 모두 글자 대비를 맞춘 색만, 자유 HEX는 받지 않음). 색을 바꾸면 달력·임박순·상세에 바로 반영된다.
- [ ] AC-20 카테고리별 보기: 달력·임박순 위에 카테고리 칩을 둔다(이미지의 공급유형 칩처럼). 칩을 눌러 켜고 끄며 여러 개를 함께 켤 수 있다. 기본은 전체 켜짐. 선택은 두 보기에서 공유하고 기억한다.
- [ ] AC-36 상태별 보기: 카테고리 칩 아래 상태 칩으로 거른다(하나만 고름, 기본 "전체"). 칩마다 개수 표시, 0개면 흐리게.
  - 상태(서버 계산): 결과 입력 필요(날짜 지난 대기 단계가 있음) / 진행 중 / 관심 공고(구독으로 들어와 [지원함] 전, AC-35) / 탈락 / 최종 합격·완료.
  - 카테고리 칩과 함께 적용(예: 민간임대 + 결과 입력 필요). 달력·임박순·표(AC-24) 모두 같은 조건, 공유(AC-25)의 저장 조건에도 포함.
  - 사용자가 적은 상태 문구(AC-23)는 칩이 아니라 검색으로 찾는다(자유 입력이라 칩이 끝없이 늘어남).
- [ ] AC-05 상세: 임박순의 줄, 달력의 날짜 또는 막대를 누르면 오른쪽에 상세가 열린다. 날짜를 누르면 그날 단계가 있는 항목 목록이 나오고, 항목을 누르면 단계 타임라인이 나온다.
- [ ] AC-21 사이드 편집: 달력·임박순에서 일정을 누르면 오른쪽 패널에 저장한 정보가 나오고 그 자리에서 고친다. 편집 필드는 제목, 내용, 상태, 이미지, 카테고리, 단계(이름·날짜·링크). 저장은 [저장] 버튼, 저장 전 패널을 닫으면 "변경 내용을 버릴까요?" 확인.
- [ ] AC-22 이미지: 항목당 최대 10장, 장당 10MB, JPG·PNG·WEBP·GIF(ADR-014 업로드 기본값과 동일). 비공개 저장, 썸네일 생성은 링크 항목과 같은 파이프라인 재사용. 패널에서 추가·삭제·순서 변경.
- [ ] AC-23 상태 직접 입력: 상태는 결과 방식의 자동 상태(진행 중/탈락/최종 합격/완료)와 별개로, 사용자가 적는 짧은 상태 문구(예: "취준", "시험 준비", "잔금 대기", 20자)를 둔다. 자동완성은 전에 쓴 문구.
- [ ] AC-24 필터 → 표: 카테고리 칩이나 기간 필터를 걸면 왼쪽이 달력에서 표(트래커) 모양으로 바뀐다. 열: 제목, 카테고리, 현재 단계, 날짜, D-day, 상태 문구. 필터를 모두 풀면 달력으로 돌아간다. [달력으로 보기]로 수동 전환도 가능.
- [ ] AC-25 공유하기: 표 위 [공유하기] → 지금 필터 조건(카테고리 + 기간)과 열 구성을 그대로 저장하고 공개 링크를 만든다. 저장하는 건 조건이라 원본이 바뀌면 공유 화면도 바뀐다(라이브). 기간은 "이번 주/이번 달/다음 7일" 같은 상대 기간 또는 고정 날짜.
  - 만들기 전 확인 창: 공개될 항목 수와 공개 범위 선택 — 제목·날짜·링크(항상), 내용(기본 켬), 이미지(기본 켬), 상태 문구(기본 켬), 합격·탈락 결과(기본 끔). 캡처에 개인정보가 있을 수 있다는 안내.
  - 공유 관리: 내 공유 목록에서 이름 바꾸기, 끄기, 링크 재발급.
- [ ] AC-26 공유 화면: 로그인 없이 표로 본다. 줄을 누르면 노션 페이지처럼 상세(제목, 카테고리, 단계 타임라인, 내용, 이미지, 연결 링크)가 열린다. 읽기 전용. 검색엔진 색인 제외.

  - 비밀 댓글: 쓸 때 [비밀로 달기]를 켜면 공유한 사람과 쓴 사람만 본다. 다른 사람에게는 "비밀 댓글이에요"와 닉네임·시간만 보인다. 쓴 사람은 같은 브라우저이거나 비밀번호를 넣으면 볼 수 있다(비밀번호 없이 쓴 비밀 댓글은 그 브라우저에서만). 공유한 사람의 답글도 같은 비밀로 이어진다. 전체 댓글 목록·개수에는 포함하되 내용은 같은 규칙으로 가린다. 이메일 알림 본문에도 내용은 넣지 않는다.
  - 댓글은 텍스트만 500자. 링크는 글자로만(자동 링크 없음).
  - 댓글은 공유 단위로 저장되고 원본 항목 쪽 사이드 패널에도 "공유에서 온 댓글"로 보인다. 공유를 지우면 댓글도 삭제.
  - 신고·운영자 처리는 백오피스(D-10) 범위.
  - 목록에서 보기: 공유 표의 줄마다 [댓글 N] 버튼(0이면 흐린 [댓글]). 누르면 오른쪽 패널이 그 항목의 댓글로 열린다. 표 위 [전체 댓글 N]은 모든 항목의 댓글을 최신순으로 모아 보여 주고, 댓글마다 어느 항목인지 표시하며 누르면 그 항목 상세로 간다.
  - 공유한 사람 쪽: 일정 페이지 표(AC-24)에도 같은 [댓글 N] 열, 읽지 않은 댓글은 점으로 표시.
- [ ] AC-33 버킷을 링크로 넣기(버킷·발행 구현 후): 일정을 직접 추가·수정할 때 링크 칸에서 [버킷 링크 넣기] → 내 버킷을 고르면 그 버킷의 **발행(공유 페이지) 링크**가 일정 링크로 들어간다. 일정에는 버킷 자체가 아니라 공유 링크가 붙는다.
  - 고른 버킷이 아직 발행 전이면 "이 버킷을 공유 페이지로 만들까요?" 확인 후 발행(이미지는 기본 비공개, ADR-014 4번). 거절하면 넣지 않는다.
  - 저장은 URL 글자 복사가 아니라 발행 참조(`publication_id`)로 한다. 발행 링크를 재발급하면 일정 쪽 링크도 자동으로 바뀌고, 발행을 끄면 "공유가 꺼진 버킷"으로 흐리게 표시한다.
  - 내 링크(북마크)에는 저장하지 않는다(내 발행 주소가 레퍼런스 목록에 섞이지 않게).
  - 일정 공유 화면(AC-26)에서 받는 사람이 이 링크를 누르면 버킷 공유 페이지로 간다. 일정 데이터는 버킷·MCP 어디로도 나가지 않는다.
  - 일괄 등록(AC-30) 카드에서도 같은 [버킷 링크 넣기]를 쓸 수 있다.
  - 버킷 화면에 [링크로 만들기] 버튼: 누르면 발행 확인 → 공유 링크 생성 → [링크 복사] [일정에 붙이기]를 보여 준다. 이미 발행된 버킷이면 바로 링크를 보여 준다. [일정에 붙이기]는 기존 일정을 고르거나 새 일정을 만들어 링크를 넣는다. (버튼은 발행 기능(로드맵 MVP '기본형 발행')의 진입점과 같은 동작이라 발행 명세와 함께 구현)
- [ ] AC-06 결과 처리: 날짜가 지난 대기 단계에 [합격] [불합격] 버튼을 보여 준다. 날짜 전에는 버튼을 숨긴다(미리 처리하는 실수 방지). 불합격이면 항목이 "탈락"으로 닫힌다.
- [ ] AC-07 다음 단계: 합격 처리하면 바로 "다음 단계 추가" 입력(이름·날짜)과 [최종 합격으로 마치기]를 보여 준다. 단계 이름은 자유 입력이고, 내가 전에 쓴 이름을 자동완성으로 보여 준다.
- [ ] AC-08 순서 규칙(합격·불합격 방식만): 마지막 단계가 대기면 새 단계를 추가할 수 없다. 완료만 방식은 언제든 추가할 수 있고 날짜순으로 정렬된다.
- [ ] AC-15 버킷에서 보기(버킷 구현 후): 버킷 안 링크 중 일정이 연결된 것이 있으면 버킷 상단에 다가오는 일정(단계·날짜)을 보여 주고, 누르면 일정 페이지 상세로 간다. 버킷과 트래커 사이에 저장된 연결은 없다.
- [ ] AC-17 링크에 표시: 일정이 연결된 링크는 내 링크·버킷 카드에 작은 날짜 표시가 붙는다.
- [ ] AC-09 알림: 단계 날짜 당일 오전 9시(Asia/Seoul)에 이메일 알림 한 번. 같은 단계로 두 번 보내지 않는다. 설정에서 알림을 끌 수 있다(기본 켜짐).
- [ ] AC-10 결과 미처리 안내: 날짜가 지났는데 대기인 단계는 달력·임박순·상세에 "결과를 입력해 주세요"를 표시한다(추가 알림은 보내지 않음).
- [ ] AC-11 되돌리기: 결과 처리를 잘못했으면 상세에서 [결과 취소]로 대기로 돌린다. 그 뒤에 추가한 단계가 있으면 취소할 수 없고, 먼저 그 단계를 지우라고 안내한다.
- [ ] AC-12 삭제: 항목 삭제는 휴지통 없이 확인 대화상자 후 삭제. 연결된 공고 링크는 지우지 않는다.
- [ ] AC-13 빈 상태: 항목이 없으면 달력·임박순 모두 "아직 지원한 일정이 없어요" + [지원 추가].
- [ ] AC-14 권한: 다른 사용자 항목은 조회·수정할 수 없다(404).

## UX 및 디자인

- 레이아웃(웹): 좌우 2단. 왼쪽 = 상단 [달력 | 임박순] 전환 + 카테고리 칩 줄 + 달력/목록. 오른쪽 = 상세 패널. 아무것도 안 골랐으면 오른쪽은 "날짜나 항목을 눌러 보세요".
- 좁은 화면: 한 단으로 바꾸고, 상세는 전체 화면으로 열고 뒤로가기로 닫는다.
- 상세 패널: 위에 이름·상태·공고 링크, 아래 단계 타임라인(세로). 대기 단계에만 결과 버튼.
- 색의 역할 분리: 색은 카테고리만 뜻한다. 상태는 색이 아니라 모양으로 — 탈락·완료는 흐리게+취소선 없이 라벨, 지난 대기는 ! 아이콘. 색만으로 구분하지 않도록 칩·막대에 카테고리 이름 첫 글자도 함께 둔다(이미지의 ⓣ① 표시처럼).
- 카테고리 관리: 칩 줄 끝 [⚙] → 이름·색 편집, 추가·삭제. 색 고르기는 팔레트 원형 버튼 12개.
- 접근성: 달력 날짜는 버튼, 화살표 키로 이동, 선택 날짜는 `aria-selected`. 전환은 탭 역할.
- 기존 컴포넌트 및 디자인 토큰 재사용: 앱 틀(FEAT-009)의 사이드 메뉴에 "지원" 메뉴 추가, 링크 고르기는 버킷의 "+ 링크 추가" 선택 UI 재사용.

## 영향도 및 주의사항

- 의존성: 버킷 테이블이 아직 없다. 링크 단위 연결이라 트래커는 버킷 없이 먼저 만들 수 있고, AC-15만 버킷 구현 후 붙인다(DB 변경 없음).
- 링크 휴지통(FEAT-002): 휴지통에 간 링크는 일정에서 "삭제된 링크"로 흐리게 표시하고, 복구하면 다시 보인다. 영구 삭제 시 연결만 null.
- 기존 Feature 및 회귀 위험: 테이블 추가만이라 북마크·인증 회귀 위험 낮음. 링크 삭제(FEAT-002) 시 `bookmark_id`를 null로 두는 처리 확인. 사이드 메뉴 변경은 FEAT-009 스냅샷 확인.
- 캐시/호출 빈도/무효화: 달력은 월 단위로 조회하고, 단계 변경 후 해당 월·목록·상세를 다시 받는다.
- 알림 작업: `@nestjs/schedule` 크론(매일 09:00 KST)으로 오늘 날짜·대기·미발송 단계를 찾아 `mail` 모듈로 발송 후 `notified_at` 기록. 서버가 여러 대가 되면 중복 발송 방지를 위해 행 잠금(`FOR UPDATE SKIP LOCKED`) 또는 `notified_at` 조건부 업데이트로 선점.
- 알림 채널 추상화: 발송부를 `TrackerNotifier` 인터페이스로 두고 지금은 이메일 구현 하나. 앱 푸시는 같은 인터페이스에 채널을 추가한다.
- 비용/보안: 이메일 발송량은 사용자당 하루 몇 건 수준. 메일 본문에 메모는 넣지 않는다(이름·단계·날짜만).
- 롤백 및 데이터 호환성: 새 테이블이라 마이그레이션 롤백은 테이블 삭제로 가능. 메뉴는 기능 플래그 없이 바로 노출(개인 사용 단계).
