# FEAT-007 — 인증 화면 디자인 적용 (AUTH-01·02·03)

- Status: Implemented
- Updated: 2026-11-13
- Related: [AUTH-01 시작 화면 기획서](https://claude.ai/artifact/8rKDnj3bEzv37kmJkBMh3o) · [AUTH-02 가입 기획서](https://claude.ai/artifact/DHH4gRnmFPXbVVWy4ukd2q) · [시작 화면 시안](https://claude.ai/artifact/GkXw4iykkY9j9GHe8DzwAj) · [회원가입 시안](https://claude.ai/artifact/MguvY2as5LXgGUiqQ2N7Ws) · spec 06·07, FEAT-003·004·006, ADR-009·012, OPEN-QUESTIONS D-09

## 목적 및 비범위

- 사용자 문제: 기능 위주 최소 화면(FEAT-006)이라 첫인상과 사용성이 약하다. 확정된 시안(B안 캐릭터 무대)대로 시작(로그인·가입 공용)·이메일 회원가입·인증 결과 화면을 다시 그린다.
- 이번 작업에서 하지 않는 것(서버 작업 필요): 동의 기록 저장 API, 소셜 첫 가입 약관 동의 화면(계정 상태 필요), 로그인 실패 문구에 소셜 안내 추가(서버 문구), 카카오 공식 버튼 에셋 교체, 수동 라이트·다크 토글, 랜딩·북마크 화면 재디자인.

## 사용자 흐름 및 수용 기준

시작 화면(`/login`)

- [ ] AC-01 첫 화면: 카카오·Google(서버가 켠 제공자만, FEAT-004 AC-11) → [이메일로 로그인] → "카카오·Google은 처음이면 자동으로 가입돼요." → "아직 계정이 없나요? 회원가입"(`/signup`). 이메일 입력창은 보이지 않는다.
- [ ] AC-02 이메일 모드: [이메일로 로그인]을 누르면 주소가 `/login?method=email`이 되고 같은 카드 안에서 이메일·비밀번호 폼으로 바뀐다. 이메일 칸에 포커스. PC에서는 제목을 한 줄(28px)로 줄여 스크롤 없이 한 화면에 보인다(1280×800·1366×768·1440×720 확인). "← 카카오·Google로 로그인"은 `/login`으로 돌아간다. 주소로 바로 들어와도 이메일 모드다.
- [ ] AC-03 최근 사용: 마지막으로 성공한 로그인 방법(kakao·google·email)의 버튼에 "최근 사용" 배지. 방법 이름만 `localStorage`에 둔다(토큰·이메일 저장 금지, FEAT-006 AC-01 유지). 소셜은 누를 때 `sessionStorage`에 후보로 두고 콜백 성공 시 확정한다. 저장소를 쓸 수 없으면 배지만 생략한다.
- [ ] AC-04 기존 동작 유지: 로그인 성공·실패·제출 중 비활성·네트워크 오류·이미 로그인 시 홈 이동(FEAT-006 AC-09·13·14), `?oauth=failed` 안내(FEAT-004 AC-13).
- [ ] AC-05 소셜 버튼 문구: "카카오 로그인"·"Google 로그인"(제공자 가이드, 07-BRAND). 카카오는 키 발급 전이어도 버튼을 보여 주고, 서버가 켜지 않았으면 누를 때 이동 없이 "카카오 로그인은 준비 중이에요" 안내만 한다(2026-11-13 사용자 결정, FEAT-004 AC-11의 "켜진 제공자만 표시"에 대한 카카오 예외). Google은 기존대로 켜졌을 때만.

이메일 회원가입(`/signup`)

- [ ] AC-06 폼: "← 카카오·Google로 시작하기"(`/login`), 이메일, 비밀번호(보기 버튼, 도움말 "8자 이상으로 입력해 주세요."), 필수 동의 3개(만 14세 이상·이용약관·개인정보 수집·이용), [가입하기], "이미 계정이 있나요? 로그인". 소셜 버튼은 없다(시작 화면으로 일원화).
- [ ] AC-07 동의: 3개를 모두 체크해야 [가입하기]가 활성. PC에서는 간격을 줄여 회원가입 화면도 스크롤 없이 한 화면에 보인다(1280×800·1366×768·1440×720 확인, 모바일 체크 행은 터치 44px 유지). 화면에서만 막으며 서버에 기록하지 않는다(비범위, 공개 전 필수 후속).
- [ ] AC-08 발송 안내: 202면 "인증 메일을 보냈어요" 화면(입력한 이메일 표시, 24시간 유효, "인증 전에도 바로 사용할 수 있어요."), [로그인하러 가기](`/login?method=email`), [메일 다시 보내기]는 60초 대기 후 활성(남은 초 표시). 재발송은 기존 API, 결과는 서버 응답대로.
- [ ] AC-09 오류: 서버 `message` 그대로(ADR-009), 입력값 유지.

인증 결과(`/verify-email`)·기타

- [ ] AC-10 인증 완료: 패밀리 캐릭터 축하 모션 + "이메일 인증이 끝났어요" + [시작하기](`/`). 확인 중·실패(서버 문구 + 재발송) 동작은 FEAT-006 AC-08 그대로.
- [ ] AC-11 비밀번호 찾기·재설정·소셜 콜백 화면: 같은 레이아웃만 입힌다. 동작 변경 없음.
- [ ] AC-12 모드·접근성: 시스템 설정으로 라이트·다크 전환. 모든 입력 라벨, 오류 `role="alert"`·입력 연결, 키보드 조작, 터치 44px, `prefers-reduced-motion`이면 모든 움직임 정지. 장식 캐릭터는 `alt=""`/`aria-hidden`.

## 데이터 계약

- 서버 소유 값: 사용 가능한 제공자 목록, 모든 오류 문구, 비밀번호 정책.
- 프론트 전용 파생 값: 이메일 모드(주소), 동의 체크 여부(제출 가능 여부), 재발송 대기 초, 최근 사용 방법(표시용).
- API: 변경 없음. 기존 login·signup·resend-verification·email-verification·password-reset·oauth 사용.
- 오류 문구: 서버 `message` 그대로. 고정 문구는 기존 `shared`의 네트워크·소셜 실패 2개만.
- DB 변경/마이그레이션: 없음.

## UX 및 디자인

- 디자인 기준: 07-BRAND v0.4(무대형 첫 화면, 모바일은 패밀리 심볼 하나·여백 24px, 주 버튼 잉크 알약형, 입력·소셜 12px, 카드 24px, 대표 캐릭터 눈 움직임, 축하 모션).
- 토큰: `globals.css`에 07-BRAND 역할 토큰(라이트·다크)을 추가한다. D-09는 "인증 화면 범위 부분 확정"으로 기록하고, 내 링크 화면 디자인 때 나머지를 확정한다.
- 공용 컴포넌트: `shared/ui/FormParts`(입력·버튼·오류·안내) 스타일을 바꾼다. 북마크 화면도 같은 입력·버튼 모양이 된다. 캐릭터·무대는 인증에서만 쓰므로 `features/auth/ui`에 둔다(두 번째 사용처가 생기면 shared로).

## 영향도 및 주의사항

- 기존 Feature 및 회귀 위험: 로그인 테스트가 입력창이 바로 보인다고 가정 → 이메일 모드로 열어 검증. 가입 화면에서 소셜 버튼 제거. 토큰 값 변경으로 홈·북마크 글자색(`#171717`→`#20212A`)이 약간 바뀐다.
- 캐시/호출 빈도/무효화: `/providers`는 시작 화면 진입 시 1회(기존). 새 API 호출 없음. 재발송 대기 타이머는 언마운트 시 해제.
- 메모리/동시성/비용/보안: 저장소에는 방법 이름만. 비용 없음.
- 롤백 및 데이터 호환성: revert. 데이터 영향 없음.

## 테스트 계획

테스트 이름은 `AC-xx: 동작 문장` 형식으로 수용 기준과 연결한다.

- Unit: 최근 사용 저장·확정·저장소 실패 시 무시(AC-03).
- Component(Vitest·Testing Library): 첫 화면에 이메일 입력 없음·[이메일로 로그인]이 이메일 모드 주소로 이동(AC-01·02), 이메일 모드에서 기존 로그인 동작(AC-04), 소셜 문구(AC-05), 동의 3개 전 비활성(AC-07), 발송 안내와 재발송 대기(AC-08), 인증 완료 화면(AC-10).
