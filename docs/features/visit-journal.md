# FEAT-013 — 방문 일지: 템플릿으로 기록하고 비교하기

- Status: Draft
- Updated: 2026-11-24
- Related: ADR-019(실험실 구조, 제안), FEAT-012(일정 트래커, 임장 타입), ADR-018(링크 원본 하나)
- 시안: Keepio 일정 트래커 시안 캔버스 보드 7(방문 일지 목록), 9(체크리스트), 11(템플릿 편집), 12(비교표)

## 목적 및 비범위

- 사용자 문제: 임장·웨딩홀 투어·스드메 상담처럼 "어딘가 다녀와서 정보를 적고, 체크하고, 결정하는" 일은 양식이 비슷한데 매번 노션에 표를 새로 만들고 손으로 비교한다.
- 해결: **템플릿**(필드 + 체크리스트 + 결과 선택지)을 한 번 만들고, 방문 기록은 템플릿 양식대로 입력한다. 같은 템플릿 기록은 **비교표**로 나란히 본다.
- 위치: 실험실 "방문 일지". **웹 전용**(모바일 앱 미제공, ADR-019). 1차 기본 템플릿은 **임장**(예시·기준). 웨딩홀 투어는 기본 제공 후보.
- 하지 않는 것: 수식·관계형 필드, 템플릿 공유·마켓, 팀 공동 편집, MCP·발행 노출, 모바일 앱.

## 개념

- **템플릿**: 이름, 목록에 크게 보일 필드 1개, 필드(최대 10개), 기본 체크리스트, 결과 선택지(기본 확정·고민중·탈락, 수정 가능).
- **필드 종류(7)**: 글자, 숫자, 금액, 날짜, 링크, 연락처, 선택지. 필드마다 필수 여부, **비교표 표시** 여부.
- **방문 기록**: 템플릿 1개를 따른다. 방문 일시(필수, 트래커 달력에 임장 타입으로 표시), 필드 값, 체크 상태, 결과, 메모.
- 기본 임장 템플릿 필드: 매물 이름(필수), 매물 링크, 방문 일시(필수), 가격(금액), 면적(㎡), 역까지(분), 부동산 이름, 연락처(선택).

## 사용자 흐름 및 수용 기준

- [ ] AC-01 목록: 템플릿 탭(임장 / 웨딩홀 투어 / + 템플릿) → 선택한 템플릿의 기록을 **월별 목록**으로 본다. [‹ 월 ›] 이동, 다른 달이면 [이번 달]. 줄: 날짜(일·요일만, 월은 머리에), 대표 필드 + 결과 태그, 위치·부동산·연락처(있을 때만), 메모 한 줄(없으면 숨김), 체크 진행률, [매물 ↗](링크 필드가 있을 때), [체크리스트].
- [ ] AC-02 상태 탭: 전체 / 방문 예정 / 결과 선택지별(고민중·확정·탈락). 방문 일시가 지나고 결과가 없으면 기본 결과(첫 선택지가 아니라 "고민중")로 본다.
- [ ] AC-03 상세(오른쪽 패널): 대표 링크 큰 버튼(예: [매물 공고 보기 ↗]), 템플릿 필드 입력, 결과 선택, 메모, 체크리스트 진행률. 연락처가 있으면 [전화](tel:).
- [ ] AC-04 체크리스트: 템플릿 기본 항목을 기록마다 체크. [편집]에서 항목 이름 수정·삭제·묶음별 추가, [기본 체크리스트로 되돌리기]. 바꾼 목록은 그 템플릿의 다음 기록부터 기본값.
- [ ] AC-05 템플릿 편집: 이름, 대표 필드, 필드 추가(10개 넘으면 막힘)·순서 변경·종류·필수·비교표 표시·삭제, 결과 선택지 추가·삭제. 기존 기록이 있는 필드를 지우면 "기록 N개의 이 값도 사라져요" 확인.
- [ ] AC-06 비교표: 같은 템플릿 기록을 표로. 열 = 대표 필드 + 비교표 표시 필드 + 체크 + 결과 + 링크. 열 제목으로 정렬(오름/내림), 숫자·금액 열은 가장 좋은 값 강조(가격·거리 낮을수록, 면적 클수록 — 필드에 "낮을수록 좋음" 옵션). 금액은 거래 유형 등 선택지 필드로 필터해야 비교(기본: 전세).
- [ ] AC-07 트래커 연동: 방문 기록은 FEAT-012 달력에 임장 타입으로 같이 보인다(데이터 하나). 청약 일정과 연결(선택).
- [ ] AC-08 권한: 본인 기록만. 다른 사용자 404.

## 데이터 계약(초안)

- `visit_templates`: id, user_id, name(20), title_field_id, result_options(jsonb, 최대 6), created_at.
- `visit_template_fields`: id, template_id, position, name(20), type(enum 7종), required, in_compare, lower_is_better(nullable). 템플릿당 최대 10.
- `visit_checklist_items`: id, template_id, group(20), position, name(40).
- `visits`: id, user_id, template_id, visited_at(timestamptz), values(jsonb: field_id → 값), result(nullable), memo(1000), tracker_link(nullable FK FEAT-012 항목), created_at, updated_at.
- `visit_checks`: visit_id, item_id, checked.
- 기본 템플릿(임장)은 가입 시 복사하지 않고 처음 방문 일지를 열 때 생성.

## 열린 질문

- 웨딩홀 투어를 기본 템플릿으로 같이 줄지(추천: 임장만 기본, 웨딩홀은 "템플릿 예시에서 추가").
- 금액 필드 단위(만 원 고정 추천).
- 비교표 최대 행 수(추천: 50, 넘으면 필터 안내).

## 테스트 계획

- Unit: 필드 값 검증(종류별), 비교표 정렬·최선값 계산, 템플릿 필드 10개 제한.
- Integration: 템플릿·필드·기록 CRUD, 필드 삭제 시 기록 값 정리, 권한 404.
- E2E: 템플릿 편집 → 기록 추가 → 체크 → 결과 → 비교표 정렬.
