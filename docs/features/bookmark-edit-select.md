# FEAT-011 — 링크 제목 수정과 여러 개 선택

- Status: Approved (구현 완료, 사용자 Mac 검증 대기)
- Updated: 2026-11-21
- Related: FEAT-002(목록·삭제·복구) / FEAT-010(제목·썸네일, AC-03 "수정은 이후 편집 기능에서", AC-06·17~20) / 시안 LINK-01 전체 링크 PC 목록형·카드형·모바일(2026-11-21) / `apps/web/src/features/bookmarks`

## 목적 및 비범위

- 사용자 문제: 스마트스토어·쿠팡처럼 서버 요청을 막는 사이트는 제목을 못 받아 `diaday · 스마트스토어`, `쿠팡 상품`만 보인다. 저장한 뒤에 제목을 고칠 방법이 없다. 여러 링크를 한 번에 지우거나 정리할 수도 없다.
- 이번 작업에서 하지 않는 것: 태그·카테고리 수정(FEAT-008), 버킷에 추가·공유 페이지 만들기·카테고리 변경의 실제 동작(각 서버 기능 전까지 선택 막대에서 "준비 중"), 휴지통의 여러 개 선택, 올린 이미지를 자동 썸네일로 되돌리기.

## 검토한 대안

제목 수정 방식:

| 선택지                                   | 장점                                            | 단점                                             |
| ---------------------------------------- | ----------------------------------------------- | ------------------------------------------------ |
| A. ⋯ 메뉴 "수정" → 그 줄에서 입력칸      | 팝업 없이 가볍다, PC·모바일 같은 자리, 시안대로 | 태그까지 고치려면 나중에 편집 시트로 넓혀야 한다 |
| B. 제목 옆 연필 버튼                     | 찾기 쉽다(PC)                                   | 모바일은 늘 띄워야 해 복잡, 제목 링크와 헷갈림   |
| C. 편집 시트(제목·태그·카테고리 한 번에) | 앞으로 확장하기 좋다                            | 지금은 제목뿐이라 과하다                         |

- 추천 및 근거: A(사용자 결정 2026-11-21, 시안 반영).

여러 개 삭제:

| 선택지                                 | 장점                                 | 단점                                             |
| -------------------------------------- | ------------------------------------ | ------------------------------------------------ |
| A. 화면이 기존 `DELETE /:id`를 여러 번 | API 추가 없음, 기존 권한·검증 그대로 | 요청 수 = 고른 개수(한 화면 최대 수십 개)        |
| B. 새 일괄 삭제 API                    | 요청 1번, 한 트랜잭션                | API·테스트 추가, 부분 실패 규칙을 새로 정해야 함 |

- 추천 및 근거: A. 한 번에 고르는 수가 불러온 목록(페이지당 기본 개수 × 더 보기)으로 제한되고, 삭제는 되돌릴 수 있는 휴지통 이동이다. 동시 요청은 4개로 묶어 보낸다. 고른 수가 많아지면(예: "전체 선택" 확장) B로.
- 관련 ADR: 없음.

## 사용자 흐름 및 수용 기준

- [x] AC-01 제목 수정: 활성 목록에서 ⋯ 메뉴 "수정"을 누르면 그 링크의 제목 자리가 입력칸(지금 보이는 제목이 채워짐, 전체 선택)으로 바뀐다. Enter·[저장]이면 저장, Esc·[취소]면 그대로 닫는다. 저장하면 `PATCH /api/bookmarks/:id { title }`. 앞뒤 공백 제거·연속 공백 1칸, 1~100자.
- [x] AC-02 제목 비우기: 비우고 저장하면 사용자 제목을 지우고(`title: null`) 표시 제목은 페이지 제목 → 사이트 이름(FEAT-010 AC-07·17~20)으로 돌아간다.
- [x] AC-03 오류: 100자를 넘기면 입력칸 아래 서버 문구, 입력칸은 오류 테두리(07-BRAND §6). 남의 링크·휴지통의 링크는 404 "링크를 찾을 수 없어요.". 저장 중에는 버튼을 막는다.
- [x] AC-04 제목 넣기 안내: 사용자 제목도 페이지 제목도 없어 사이트 이름으로 보이는 링크는 제목 끝에 "제목 넣기"(작은 글자 버튼)를 보여 주고, 누르면 AC-01 입력칸이 빈 채로 열린다. 서버가 `titleSource: "user" | "page" | "site"`로 알려 준다.
- [x] AC-05 이미지 바꾸기 이동: 썸네일을 눌러 이미지를 바꾸던 동작(FEAT-010 AC-06 후속)을 ⋯ 메뉴 "이미지 바꾸기"로 옮긴다. 썸네일은 누르면 링크를 고른다(AC-06). 메뉴 순서: 수정 → 이미지 바꾸기 → (구분선) → 삭제.
- [x] AC-06 선택: 썸네일 왼쪽 위 체크박스(흰 바탕·그림자, 고르면 잉크 + 흰 체크, 누르는 영역 44px)로 링크를 고른다. PC는 마우스를 올린 썸네일과, 하나라도 고르면 모든 썸네일에 보인다. 목록 제목 앞 체크박스는 불러온 링크를 모두 고르거나 푼다(일부만 고르면 중간 상태). 목록형·카드형이 같다.
- [x] AC-07 모바일 선택 모드: 목록 제목 옆 "선택"을 누르면 모든 썸네일에 체크박스가 나오고 머리는 "N개 선택 · 완료", 아래 하단 탭 자리에 작업 막대가 나온다. "완료"·뒤로 가기면 선택을 풀고 나간다.
- [x] AC-08 작업 막대: 하나라도 고르면 "N개 선택 · 버킷에 추가 · 공유 페이지 만들기 · 카테고리 변경 · 삭제 · ✕"가 화면 아래에 붙는다. 버킷·공유 페이지·카테고리는 서버 기능 전까지 "준비 중"(누를 수 없음, 화면 읽기에 "(준비 중)"). ✕·Esc는 선택을 푼다.
- [x] AC-09 여러 개 삭제: "삭제"를 누르면 고른 링크를 휴지통으로 옮긴다(기존 삭제와 같음, 확인 창 없음 — 휴지통에서 복구). 끝나면 "N개를 휴지통으로 옮겼어요"를 알리고 선택을 푼다. 일부가 실패하면 성공한 것만 빠지고 "N개는 옮기지 못했어요. 다시 시도해 주세요."와 실패한 링크는 계속 고른 상태로 둔다.
- [x] AC-10 보기 전환·새로 고침: 목록형 ↔ 카드형을 바꿔도 고른 링크는 유지한다. 다시 불러온 목록에 없는 링크(삭제됨 등)는 선택에서 빠진다. 휴지통에는 체크박스·수정·이미지 바꾸기가 없다.

## 데이터 계약

- 서버 소유 값: 제목 정규화·길이 검사(FEAT-010 AC-01과 같은 규칙), 표시 제목과 그 출처(`titleSource`).
- 프론트 전용 파생 값: 고른 링크 ID 목록(화면 상태, 새로 고침하면 사라짐), 수정 중인 링크 ID.
- API:
  - `PATCH /api/bookmarks/:id` body `{ title: string | null }` → 200 북마크(기존 응답 형식). 활성 북마크만. `title`이 빈 문자열이거나 공백뿐이면 `null`과 같다.
  - 북마크 응답에 `titleSource: "user" | "page" | "site"` 추가(`displayTitle`을 무엇으로 만들었는지).
  - 여러 개 삭제는 기존 `DELETE /api/bookmarks/:id`를 화면이 여러 번(동시 4개).
- 오류 문구(ADR-009, 서버 `message` 그대로 표시):

  | status | code              | 상황                      | 문구                               |
  | ------ | ----------------- | ------------------------- | ---------------------------------- |
  | 400    | VALIDATION_FAILED | 제목 100자 초과           | 제목은 100자까지 입력할 수 있어요. |
  | 404    | NOT_FOUND         | 없거나 남의·삭제된 북마크 | 링크를 찾을 수 없어요.             |

- DB 변경/마이그레이션: 없음(`bookmarks.title` 그대로).

## UX 및 디자인

- 시안: LINK-01 전체 링크 PC 목록형(제목 수정 중·⋯ 메뉴·썸네일 안 체크박스·작업 막대), PC 카드형(체크박스·작업 막대), 모바일(⋯ 메뉴, "선택"). 고른 줄에 회색 배경을 주지 않는다(사용자 결정).
- 입력칸: 포커스 잉크·오류 빨강 테두리(07-BRAND §6), 아래 한 줄 "Enter 저장 · Esc 취소 · 비우면 페이지 제목으로 돌아가요". 수정 중에는 그 줄의 태그를 숨긴다.
- 접근성: 체크박스 이름 "선택: {제목}", 모두 선택 "이 화면의 링크 모두 선택", 작업 막대 `role="toolbar"`, 삭제 결과는 `role="status"`로 알림. 수정이 끝나면 포커스를 ⋯ 버튼으로 돌린다.
- 기존 컴포넌트: `BookmarkList`·`BookmarkThumb`·`RowMenu`·`FaviconTile`, 토큰 `--shadow-soft`·`focus-ring`·`destructive`.

## 영향도 및 주의사항

- 기존 Feature 및 회귀 위험: 썸네일 누르기 동작이 이미지 바꾸기 → 선택으로 바뀐다(FEAT-010 AC-06 후속 변경). 북마크 응답 필드 추가(추가만). 제목 링크(원본 열기)는 그대로.
- 캐시/호출 빈도/무효화: 수정·삭제 뒤 목록 쿼리를 무효화(기존 `useInvalidateBookmarkLists`). 여러 개 삭제는 끝난 뒤 한 번만 무효화.
- 메모리/동시성/비용/보안: 수정은 본인·활성 북마크만(`userId` 조건). 동시 삭제 4개 제한.
- 롤백 및 데이터 호환성: DB 변경 없음, revert로 복구.
