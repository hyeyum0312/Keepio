## 목적 및 비범위

- 사용자 문제: 로그인 뒤 화면이 최소 UI(저장 + 목록 탭)라 서비스의 구조(정리 → 버킷 → 공유)가 보이지 않는다.
- 이번 작업에서 하지 않는 것: 서버 API 변경, 검색, 카테고리 칩 동작(FEAT-008), 버킷·공유 페이지·설정 기능, 링크 목록 화면 디자인 정리, 다중 선택.

## 검토한 대안

| 선택지                                                            | 장점                                   | 단점                               |
| ----------------------------------------------------------------- | -------------------------------------- | ---------------------------------- |
| A. 서버 없는 섹션도 샘플 데이터로 실제 홈에 표시                  | 디자인이 바로 다 보인다                | 가짜 데이터가 사용자 화면에 나간다 |
| B. 실제 홈은 데이터 있는 섹션만, 디자인 확인은 개발 전용 미리보기 | 사용자 화면은 정직, 디자인도 확인 가능 | 미리보기 경로 관리 필요            |

- 추천 및 근거: B(사용자 결정 2026-11-16). 비어 있는 섹션은 숨긴다는 홈 규칙과 맞다.

- 버튼 순서: 카테고리가 있으면 [카테고리 선택] [저장] [건너뛰기], 이미 카테고리를 정한 링크는 그 카테고리가 골라진 채로. 카테고리가 하나도 없으면 [+ 카테고리 만들기] [저장] [건너뛰기](예시 화면뿐 아니라 실제 홈도). 만들기와 그때의 저장은 카테고리 서버(FEAT-008) 전까지 "준비 중".
- 전체 링크 화면의 카테고리별 보기(칩)는 시안만 있고 FEAT-008 때 구현한다.

## 후속 변경 (2026-11-21, "전체 링크" → "내 링크")

- `/links` 화면 이름을 "내 링크"로 바꾼다(사용자 결정: 저장·카테고리별 보기·수정·버킷 추가까지 하는 곳이라 "전체 링크"는 좁다). 사이드바 메뉴·화면 제목(이제 화면에 보인다, 시안)·미리보기 제목. 주소(`/links`)와 모바일 하단 탭 "링크"는 그대로.
- 시안의 카테고리 칩과 "고른 칩 이름" 목록 제목(전체·미분류·디자인…)은 FEAT-008 때 구현한다. 그 전까지 목록 제목은 "정리한 링크".

## 후속 변경 (2026-11-21, 사이드바 정리·전체 보기)

- 사이드바: 홈 · 내 링크 · 버킷 · 공유한 페이지 · MCP 연결. "카테고리" 메뉴는 없앤다(사용자 결정): 카테고리별 보기는 내 링크의 카테고리 칩, 관리(이름 바꾸기·합치기·삭제·순서)는 칩 줄의 관리 메뉴로(FEAT-008). 시안의 "미분류"·휴지통 메뉴도 뺀다(미분류는 칩, 휴지통은 계정 메뉴). 모바일 하단 탭(홈·링크·버킷·공유)과 같은 구조.
- 홈 "최근 추가한 링크"의 "전체 보기"는 내 링크(`/links`)로 간다.
