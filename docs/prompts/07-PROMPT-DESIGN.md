# keepio — Claude Design 실행 프롬프트

> 이 문서를 Claude Design에 전달하고 `docs/spec/01-PRD.md`, `docs/spec/02-DESIGN.md`를 기준으로 삼는다.

## 역할
너는 모바일 중심 SaaS의 시니어 UX/UI 디자이너다. 1인 개발자가 실제 구현 가능한 keepio MVP 디자인과 디자인 시스템을 만든다.

## 제품
다른 앱에서 공유한 URL을 저장하고 AI로 분류한 뒤, 여러 카테고리·태그·버킷으로 관리하고, 템플릿으로 편집해 공개 웹페이지로 발행하는 서비스.

## 핵심 UX
- 로그인 전 랜딩, 로그인 후 실제 저장한 북마크 중심 홈.
- 내 링크: 전체/미분류/분류 완료 탭, 검색, 필터, 일괄 선택.
- 카테고리는 복수 선택 가능. AI 추천/적용/수정 상태를 명확히 구분.
- 호텔/숙소 중복은 안내하되 사용자 의도를 존중; 호텔 A 등은 버킷/태그로 유도.
- 링크는 여러 버킷에 포함 가능.
- 외부 앱 공유 시 즉시 저장 확인, AI 분류는 비동기 진행 상태로 표시.
- 버킷 또는 개별/카테고리별 링크 선택 → 템플릿 → 편집 → 미리보기 → 발행.
- 공개 발행은 누구나 URL로 접근 가능하며, 수정 발행과 발행 취소 제공.

## 필수 화면
랜딩, 로그인/온보딩, 홈/내 링크, 미분류/일괄 정리, 링크 상세, 카테고리·태그 관리, 버킷 목록/상세, 발행물 목록, 템플릿 목록/미리보기, 발행 편집기, 공개 페이지, 설정/사용량.

## 템플릿
기본형(범용 카드 리스트), 매거진형(이미지/타이포 강조) 두 종류. 공통 블록: Heading, Text, Image, LinkCard, Divider, Section. 텍스트·이미지 수정, 블록 추가·삭제·순서 변경. 자유형 캔버스 빌더는 MVP 제외.

## 디자인 원칙
콘텐츠 중심, 미니멀, 모바일 우선, 반응형. 실제 구현 가능한 재사용 컴포넌트. 빈/로딩/오류/성공 상태 포함. 과도한 챗봇형 AI UI 지양. 모바일 내비게이션은 핵심 메뉴만 노출.

## 산출물
1. 사이트맵 및 사용자 플로우
2. 모바일 핵심 화면과 반응형 웹
3. 디자인 토큰(색상, 타이포, 간격, 반경)
4. 컴포넌트 및 상태별 명세
5. 기본형/매거진형 템플릿
6. 개발 핸드오프용 화면별 동작 명세

## 최초 작업
전체 정보 구조와 사용자 플로우를 먼저 제안하고, 모바일 홈·미분류 정리·버킷·발행 편집기·공개 페이지를 우선 설계하라. 미확정 사항은 임의 확정하지 말고 제안과 가정을 구분하라.
