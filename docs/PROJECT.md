# Keepio — 프로젝트 개요

> 이 문서는 Keepio 제품의 의도·구조·디자인 원칙을 정의한다. 기능을 구현하거나 UI를 만들 때 이 문서의 용어와 규칙을 따른다.

## 한 줄 정의

인스타·블로그·유튜브 등에서 모은 링크를 AI가 자동 분류하고, 사용자가 컬렉션으로 묶어 **비교·결정까지** 하는 링크 큐레이션 앱.

## 해결하는 문제

사람들은 SNS·웹에서 "나중에 봐야지" 하고 링크를 쏟아내듯 저장하지만, 정리가 안 돼서 결국 다시 못 찾고 사라진다. Keepio는

- **저장하는 순간** AI가 콘텐츠 타입을 자동 분류하고,
- 사용자는 자기 프로젝트(여행·결혼준비 등) 단위로 자유롭게 묶을 수 있게 해서

"쌓아두기만 하는 쓰레기통"이 되지 않도록 한다.

## 핵심 구조 — 두 개의 독립적인 분류 축

| 축 | 주체 | 의미 | 예시 |
|---|---|---|---|
| **카테고리** | AI 자동 | 콘텐츠 본질 타입 | 카페·호텔·맛집·아티클·영상·장소·책·음악 |
| **컬렉션** | 사용자 직접 | 프로젝트·맥락 단위 (중첩 가능) | 교토 여행, 결혼 준비, 강릉 > 가족여행 > 호텔 |

- 한 링크는 **카테고리 1개 + 여러 컬렉션**에 동시에 속할 수 있다.
- AI는 **추천만**, 최종 **결정은 사용자**.

## 주요 기능 5단계

1. **저장** — 외부 앱 공유 시트 / 앱 내 `+` 버튼 / URL 직접 입력 모두 **동일한 통합 시트**로. 카테고리·컬렉션 선택은 자유, 저장은 1초.
2. **분류** — AI 자동 카테고리 + 미분류 누적 시 다중선택 + AI 자연어 검색("강릉 호텔 관련 찾아줘")으로 일괄 정리.
3. **컬렉션** — 재귀 중첩 구조. 자식 있으면 **카드 그리드**, 말단이면 **리스트**.
4. **비교** — 컬렉션 안 후보가 모이면 AI가 카테고리에 맞는 비교 템플릿(**스펙형 / 무드형 / 일정형 / 허브형**)을 자동 선택.
5. **결정** — 비교 후 결정하면 **결정 도우미**에 누적, 나중에 회상 가능.

### 아이템 카드

- 타입별로 다른 필드를 가진다.
  - 호텔: 박당 가격·방 타입
  - 영상: 자막 요약
  - 아티클: AI 3줄 요약
- **AI 자동 추출 정보**(검은 텍스트)와 **사용자 직접 입력**(옅은 회색 dashed)을 시각적으로 구분한다.
- 출처와 메모는 모든 타입 공통.

## 화면 흐름 (와이어프레임 기준)

1. **핵심 여정** — 스플래시 → 로그인(Google/카카오/Apple) → 링크 추가(URL 입력) → 카테고리·컬렉션 선택 → 저장. 모든 화면 iPhone 13/14 기준 **375 × 812**.
2. **홈** — 두 상태: 첫 진입(빈 홈) / 활성 사용자(컬렉션 있음). 하단 탭바로 이동.
3. **저장한 링크 목록** — 라이브러리 탭. 상단 미분류 + 하단 분류됨. 개별 분류는 `[분류함]`, 일괄 분류는 헤더 `[선택]`.
4. **도메인별 컬렉션** — 여행·결혼·쇼핑·모임. 서브 컬렉션 카드 탭하면 안으로, 헤더 `<`로 위로.
5. **비교하기 / 선택하기** — 후보가 모이면 AI 비교 도우미. 비교 UI 4종 템플릿(스펙 / 무드 / 일정 / 허브).
6. **아이템 카드 타입** — 카테고리별 카드 구조 차이.
